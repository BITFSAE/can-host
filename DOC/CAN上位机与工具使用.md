# CAN 上位机与工具使用

本文说明页面、连接、安全边界、异常处理和现场验证。安装与发布见 [`开发与发布.md`](开发与发布.md)，风扇标定细节见 [`风扇标定与手动调试指南.md`](风扇标定与手动调试指南.md)，精确接口权威位置见[文档索引](README.md)。

## 1. 职责与连接

| 功能 | 连接 | 主要用途 |
|---|---|---|
| BMS 主监视 | CAN1、BMS CANB、模拟或回放 | BMS 页面、参数命令、记录回放 |
| 整车 | 独立 CANB 或模拟 | SOP、PDM、ECU、胎温、能量计和两套风扇 |
| 台架模拟从控 | 独立 CAN1 | 向真实 F405 注入 138 串电压和 48 路温度 |
| IVT 配置 | 独立 CAN1 | 读取、配置和核对真实 IVT-S |
| MQTT | 独立只读网络连接 | 显示遥测故障和本次会话变化 |

BMS 主监视与整车连接可以同时工作；CAN1 与 BMS CANB 在 BMS 主服务内互斥。进入页面不会切换其他连接。台架和 IVT 页使用顶栏连接并隐藏底栏，其余页面使用底部连接栏。

数据无效或超时统一显示“等待数据”，不以 0 或旧值代替。源码运行和 macOS 过渡版提供“调试模拟”；模拟不经过驱动和实体总线，不能用于实车验收。

CAN 连接设置、MQTT 订阅和软件更新弹窗可点击遮罩空白处关闭。涉及参数写入、通用发送、IVT 或风扇命令的确认弹窗不会因点击遮罩关闭，必须明确取消或完成确认。

## 2. 使用流程

### 2.1 BMS 监视

1. 点击底部 `CAN1` 连接 F405、从控和自有 IVT；只读查看整车镜像时使用 `BMS CANB`。
2. 在“运行总览”确认状态机、告警和电气量，再进入“电芯与温度”或“故障与记录”定位。
3. 需要写参数时进入“参数与命令”。发送成功不等于主控接受，必须以统一应答和周期回报为准。

CAN1 显示 138 串原始电压和 48 路温度。单体值 `≤2100 mV`、`≥5400 mV` 或 `0xFFFF` 时，该通道显示“断”并从极值、压差判断中排除；同帧其他通道继续使用。温度 `0xFF` 只使对应通道显示“断”。

RTC 校时写入上位机本地时间。故障变化、CSV 和 `.bmslog` 使用上位机接收时间；主控 Flash 日志使用主控 RTC。

### 2.2 整车总览

点击底部 `整车 CANB` 连接独立整车服务。并行使用 BMS 时应选择另一条可用 PCAN 通道。

| 卡片 | 数据来源 | 页面判定 |
|---|---|---|
| SOP | `0x4A0/0x4A3/0x4A4` | 校验配对 CRC 和 ECU 确认；BMS 未进入放电 `HV_ON` 时无数据属正常 |
| BMS 镜像 | `0x4B0/0x4B1` | 电压、电流、SOC 分别使用有效位 |
| 自有 IVT-S | BMS CAN1 `0x512..0x519` | 每通道独立判断新鲜度和结果状态 |
| 赛会能量计 | `0x521/0x522/0x526/0x528` | 未收到可选功率/能量帧时显示“未发送” |
| PDM | `0x5A0/0x5A1` | 四字段均为无效值时判对应 INA226 离线 |
| ECU | `0x502/0x505..0x509` | 按 FL/FR/RL/RR 显示状态、转速、扭矩和温度 |
| 胎温 | `0x071..0x074` | 按帧 ID 分组；轮位对应仍待实物确认 |

底部快捷栏显示低压、高压、SOC、SOP 和风扇常看值。高压和 SOC 优先使用 BMS 主连接，缺失时回退整车 `0x4B0`；其他值无数据时显示“等待”。

### 2.3 CAN 监视、记录与发送

CAN 监视器用“连接 1 / 连接 2”选择现有数据流。接收区按 CAN ID 和帧类型汇总，显示最新数据、周期、次数和最近内容变体。

真实 PCAN 连接可自动或手动保存 `.bmslog`，并导出 CSV 或加载历史回放。通用发送支持单发和 20..60000 ms 周期发送，目标始终是当前选择的真实连接；模拟和回放不可写。F405、IVT 和两套风扇等已登记命令 ID 会被拒绝，必须从专用页面发送。

### 2.4 台架模拟从控

1. 展开“工程工具”，进入“台架模拟从控”。
2. 选择连接 F405 CAN1 的 PCAN，按 500 kbit/s 连接。
3. 启动默认数据后，再用快捷按钮或命令框注入电压、温度、离线和断线场景。
4. 下一组测试前点击“恢复默认”。

台架只发送六个从控的 36 帧电压和 6 帧温度，不发送 IVT、充电机或 IMD 数据。常用命令示例：

```text
cell 1 3900
temp 1 40
slave 2 online off
scenario openwire on 1
```

### 2.5 IVT 配置

配置前断开其他节点，只保留 PCAN 与目标 IVT，并使 PCAN 位率与设备当前位率一致。

1. 点击“读取并核对”。页面依次尝试出厂地址 `0x411/0x511` 和 BMS 目标地址 `0x410/0x51A`。
2. 结果为“已配置且一致”时无需重复写入；“未配置”或“配置不符”时展开差异。
3. 核对目标地址、上电模式、过流阈值和八个结果周期，再点击“配置为 BMS CAN1”。
4. 等待设备保存、重启和自动重读；以“已配置且一致”为完成信号。
5. 断开配置 PCAN，将 IVT 接入 F405 CAN1 后核对 `0x512..0x519`。

默认周期为电流 I 20 ms，其余通道 100 ms；F405 当前约 360 ms 判通道超时。旧 Legacy 链路的 250/500 kbit/s 切换只改变位率，不改变结果帧和地址。

### 2.6 两套风扇

整车 FanController 和 F405 电池箱风扇都使用 `整车 CANB`。手动、关闭、标定、保存和清除均要求真实 PCAN、逐次确认和匹配应答；手动或关闭租约为 1..60 秒，到期自动恢复温控，上位机不为普通手动操作续租。

页面显示实际占空比、转速、供电来源、限功率原因、故障和保存状态。完整标定条件、扫描步骤、保存证据和验收记录只维护在 [`风扇标定与手动调试指南.md`](风扇标定与手动调试指南.md)。

### 2.7 MQTT 遥测故障

在“遥测故障”中配置 Broker、Topic、只读账号和 TLS。默认 Topic 为 `fsae/telemetry/v1`；拒绝 `#`、`+` 通配符，且没有发布接口。

页面优先解析 `battery_fault_code`，兼容旧 `fault_code`，并核对 `alarms` 位图。连续 3 秒没有有效 Payload 时恢复“等待数据”；损坏或无已知字段的 Protobuf 只增加解析失败计数，不覆盖上一条有效记录。

连接参数保存在本机 WebView 存储中。当前 1883 连接为明文时，不应在共用电脑保存密码。协议权威源为 `vehicle-interfaces/telemetry/fsae_telemetry.proto`。

## 3. 接口与安全边界

| 连接 | 位率 | 允许发送 |
|---|---:|---|
| BMS CAN1 | 500 kbit/s | F405 专用工具命令 |
| BMS CANB | 500 或 Legacy 250 kbit/s | 只读 |
| 整车 CANB | 通常 500 kbit/s | 两套风扇专用命令；经确认的通用帧 |
| 台架 CAN1 | 500 kbit/s | 六个从控模拟帧 |
| IVT 配置 CAN1 | 与设备当前位率一致 | IVT 厂商配置命令 |

- 上位机解析只在 `canhost/decoders.py` 定义；精确帧格式由对应固件与 vehicle-interfaces 管理。
- F405 参数命令仅从 CAN1 发送，并要求新鲜状态、匹配协议版本、请求计数和应答。预充或高压闭合期间由主控继续执行最终门控。
- 两套风扇命令仅从整车 CANB 发送。即使电池箱风扇由 F405 驱动，也不能从 BMS CAN1 或只读 BMS CANB 下发。
- IVT 配置前必须确认总线上只有目标设备；模拟、回放和主监视连接不能执行配置。
- 每次通用发送都要确认物理总线、帧 ID、数据和周期；页面角色不代表实际接线。
- MQTT 只读订阅不占用 CAN 连接，也不提供远程命令。

## 4. 异常处理

| 现象 | 检查 |
|---|---|
| 等待 CAN 数据 | 对应连接、PCAN 通道、位率、节点供电和接线 |
| 第二条连接失败 | 同一 PCAN 通道可能已被占用；释放句柄或换通道 |
| 主控命令被拒绝 | BMS CAN1、主控状态、协议版本、状态新鲜度和应答原因 |
| macOS 找不到 PCBUSB | 安装 arm64 `libPCBUSB` 0.13+ 到 `/usr/local/lib`，先用 MacCAN Monitor 验证 |
| IVT 读取超时 | 设备供电、当前位率、总线唯一性和出厂/目标地址 |
| 切换 IVT 位率后无 Alive | 用目标位率重连；失败时回原位率排查 |
| 风扇命令无应答 | 整车 CANB、500 kbit/s、控制器供电和对应应答帧 |
| PDM 显示 INA226 离线 | 检查 PDM 供电与 I2C；定义见 PDM `Doc/CAN接口.md` |
| MQTT 拒绝或持续等待 | 只读凭据、Topic、Broker 桥接、接收计数和最近错误 |
| MQTT 解析失败增加 | 核对发送端 Proto 与本仓库生成代码版本 |

## 5. 调试与验证

1. 先在低压、无高压输出条件下确认 PCAN 通道和位率。
2. 使用源码或 macOS 调试模拟检查页面与解析；不要据此判断硬件正常。
3. 台架注入过压、欠压、温度、离线和断线，核对 F405 告警与页面。
4. 实车 CANB 逐卡核对原始帧和显示；IVT 配置后重新接入 CAN1 验证八通道。
5. 所有写操作同时保存请求、应答和周期回报；持久化配置需断电重启复核。

自动测试覆盖范围和未完成的实体检查见 [`../todo.md`](../todo.md)。F405 高压动作、故障复位和 Flash 日志按 BMS-MASTER-F405 的 `DOC/调试与台架测试.md` 执行。
