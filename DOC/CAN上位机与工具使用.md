# CAN 上位机与工具使用

本文说明页面、连接、安全边界、异常处理和现场验证。安装与发布见 [`开发与发布.md`](开发与发布.md)，风扇标定细节见 [`风扇标定与手动调试指南.md`](风扇标定与手动调试指南.md)，精确接口权威位置见[文档索引](README.md)。

## 1. 职责与连接

| 功能           | 连接                       | 主要用途                                           |
| -------------- | -------------------------- | -------------------------------------------------- |
| BMS 监视       | CAN1、统一 CANB、模拟或回放 | BMS 页面、参数命令、记录回放                      |
| 整车           | 统一 CANB 或模拟            | SOP、PDM、ECU、胎温、能量计和两套风扇             |
| 台架模拟从控   | 独立 CAN1                  | 向真实 F405 注入 138 串电压和 48 路温度            |
| IVT 配置       | 独立 CAN1                  | 读取、配置和核对真实 IVT-S                         |
| MQTT           | 独立只读网络连接           | 显示遥测故障和本次会话变化                         |
| 本地遥测模拟器 | MQTT、串口和/或独立 PCAN   | 生成网关联调所需的 TelemetryFrame 与 CAN1 模拟流量 |

底栏按两条物理总线提供独立的 `CAN1`、`CANB` 连接。CAN1 与 CANB 可以用双通道 PCAN 同时工作；CANB 只打开一个 PCAN 句柄，同一接收流同时供给 BMS 镜像和整车协议，不再为两类页面重复连接。进入页面不会切换其他连接。台架、IVT 和本地遥测模拟器页使用顶栏控制并隐藏底栏，其余页面使用底部连接栏。

数据页顶部有连接提示条：运行总览和故障页可使用 CAN1 或 CANB 的 BMS 镜像，CAN1 与 CANB 同时在线时优先 CAN1；电芯页和 F405 参数命令必须使用 CAN1，整车页与风扇页使用 CANB。正确连接后提示自动隐藏。

CAN1 与 CANB 疑似接反只提醒、不改变后端命令门控：真实 PCAN 连接持续（相邻证据不超过 2 秒、至少 2 帧，停止 3 秒后页面判定自动消失）收到只存在于对侧总线的帧时判定——CAN1 档案收到整车 CANB 节点帧（如 `0x5A0..0x5AE`、`0x4A0/0x4B0` 系列、Chroma），或 CANB 档案收到 F405 周期帧及从控逐串帧等 CAN1 专属扩展帧。每次连接只弹窗提醒一次，相关页面顶部显示“总线疑似接反”警示条；参数与命令页的 CAN1 徽标显示“CAN1 疑似接反”。两条实体连接同时报告接反且占用不同通道时，弹窗提供“交换通道并重新连接”：后端在执行前再次核对双向接反证据和风扇标定状态，在同一把连接锁内按实际占用通道对调并重连；任一路失败时恢复原连接，全部成功后才写入本地通道分配。只有一路报告接反时不提供交换，因为更可能是这根线插错了总线。模拟、回放和台架模式不参与。

程序启动、打开 CAN 连接设置及进入 PCAN 工具页时，会通过 PCAN-Basic 自动枚举当前已连接通道。设置弹窗直接把 PCAN 通道分配给电池箱 CAN1 和整车 CANB；自动检测到至少两路时默认选择不同通道。两张总线卡片之间的交换按钮在两项相同时把 CANB 分给下一条通道，已经错开时则交换两路。两项选到同一通道时允许保存以兼容单通道轮换：页面提示两条总线不能同时在线，此时点击连接另一条总线会在同一把连接锁内自动断开当前连接、把通道切换过去并弹出普通状态提示；目标连接失败时自动恢复原连接，对侧风扇标定进行中时拒绝切换，需先停止标定。下拉框显示句柄、设备名、设备内 CAN 通道号和“可用/已占用”状态；例如双通道 PCAN-USB Pro FD 通常显示为 `PCAN_USBBUS1` 与 `PCAN_USBBUS2`。插拔设备后可点击“刷新设备”。Windows 上以 `PCAN_ATTACHED_CHANNELS` 的结果为准；旧版 MacCAN/PCAN-Basic 不支持该参数时回退到手动通道列表，不会假定实际有两个物理通道，双通道用户可点击自动分配后再按接线核对。自动枚举成功但结果为空时不会虚构默认句柄。

无效数据不会以 `0` 冒充读数。已经解码成功的电芯、整车、PDM 和风扇监视值在超时后保留本次连接的最后样本，并用黄色“已过期”、距今秒数或快捷栏“旧”标记，不能把它理解为当前值；断线码、无效位和 PDM INA226 离线仍显示失效或“等待数据”。F405 的当前值有效性、安全状态以及主控和两套风扇是否允许下发命令仍严格按各自的新鲜度窗口判断。“调试模拟”只在本地源码运行时显示，Windows 与 macOS 发布包均不提供；模拟不经过驱动和实体总线，不能用于实车验收。

CAN 连接设置、MQTT 订阅、软件更新、更新完成和版本历史弹窗可点击遮罩空白处关闭。涉及参数写入、通用发送、IVT 或风扇命令的确认弹窗不会因点击遮罩关闭，必须明确取消或完成确认。

## 2. 使用流程

### 2.1 BMS 监视

1. 点击底部 `CAN1` 连接 F405、从控和自有 IVT；只接整车总线查看 BMS 镜像时点击 `CANB`。
2. 在“运行总览”确认状态机、告警和电气量，再进入“电芯与温度”或“故障与记录”定位。
3. 需要写参数时进入“参数与命令”。发送成功不等于主控接受，必须以统一应答和周期回报为准。

CAN1 显示 138 串原始电压和 48 路温度。单体值 `≤2100 mV`、`≥5400 mV` 或 `0xFFFF` 时，该通道显示“断”并从极值、压差判断中排除；同帧其他通道继续使用。温度 `0xFF` 只使对应通道显示“断”。超过 350 ms 的正常样本作为诊断用最后有效值继续显示，卡片直接标出距今秒数；它不会恢复为当前有效值，也不作为允许下发命令的依据。上车从控应以 15 ms/帧连续发送；若大量卡片持续显示“已过期”，应检查从控是否误开 70 ms/帧的 `debug` 模式或 CAN 丢帧。

RTC 校时写入上位机本地时间。故障变化、CSV 和 `.bmslog` 使用上位机接收时间；主控 Flash 日志使用主控 RTC。

### 2.2 整车总览

点击底部 `CANB` 建立统一的整车总线连接。该连接同时解码 BMS 镜像和其他整车节点；并行连接 CAN1 时必须在连接设置中选择另一条 PCAN 通道。

| 卡片       | 数据来源                  | 页面判定                                                        |
| ---------- | ------------------------- | --------------------------------------------------------------- |
| SOP        | `0x4A0/0x4A3/0x4A4`       | 校验配对 CRC 和 ECU 确认；BMS 未进入放电 `HV_ON` 时无数据属正常 |
| BMS 镜像   | `0x4B0/0x4B1`             | 电压、电流、SOC 分别使用有效位                                  |
| 自有 IVT-S | BMS CAN1 `0x512..0x519`   | 每通道独立判断新鲜度和结果状态                                  |
| 赛会能量计 | `0x521/0x522/0x526/0x528` | 未收到可选功率/能量帧时显示“未发送”                             |
| PDM        | `0x5A0/0x5A1`             | 四字段均为无效值时判对应 INA226 离线                            |
| ECU        | `0x502/0x505..0x509`      | 按 FL/FR/RL/RR 显示状态、转速、扭矩和温度                       |
| 胎温       | `0x071..0x074`            | 按帧 ID 分组；轮位对应仍待实物确认                              |

整车卡片按各帧独立判断数据年龄。超过页面新鲜度窗口后，SOP、BMS 镜像、能量计、PDM、ECU 和胎温保留最后有效值并明确标为“已过期”；从未收到、解码无效和 PDM 离线不复用旧值。趋势曲线只追加新鲜样本。

底部快捷栏显示低压、高压、SOC、SOP 和风扇常看值。高压和 SOC 优先使用新鲜的 CAN1 汇总帧，回退新鲜的 CANB `0x4B0`；两边都过期时显示较新的最后有效样本并加“旧”标记，悬浮可查看年龄。从未收到或无效时显示“等待”。

### 2.3 CAN 监视、记录与发送

CAN 监视器用 `CAN1 / CANB` 选择现有物理数据流。接收区按 CAN ID 和帧类型汇总，显示最新数据、周期、次数和最近内容变体。加载历史记录后，主数据源按档案中的总线类型显示为“回放 CAN1”或“回放 CANB”，不会把 CANB 记录标成实体 CAN1。

底部 `CAN1 / CANB` 两个实体连接按钮只负责连接和断开；操作成功后保留当前页面，并把监视器的数据源预选到刚连接的总线。

真实 PCAN 连接可自动或手动保存 `.bmslog`，并导出 CSV 或加载历史回放。通用发送支持单发和 20..60000 ms 周期发送，目标始终是当前选择的真实连接；模拟和回放不可写。F405、IVT 和两套风扇等已登记命令 ID 会被拒绝，必须从专用页面发送。

### 2.4 台架模拟从控

1. 展开“工程工具”，进入“台架模拟从控”。
2. 选择连接 F405 CAN1 的 PCAN，按 500 kbit/s 连接。
3. 启动默认数据后，再用快捷按钮或命令框注入电压、温度、离线和断线场景。
4. 下一组测试前点击“恢复默认”。

台架只发送六个从控的 36 帧电压和 6 帧温度，不发送 IVT、充电机或 IMD 数据。常用命令示例：

```text
cell 1 3900
temp 1 40
slave 2 online off
scenario openwire on 1
```

### 2.5 IVT 配置

配置前断开其他节点，只保留 PCAN 与目标 IVT，并确认设备已使用 CAN1 500 kbit/s。

1. 点击“读取并核对”。页面依次尝试出厂地址 `0x411/0x511` 和 BMS 目标地址 `0x410/0x51A`。
2. 结果为“已配置且一致”时无需重复写入；“未配置”或“配置不符”时展开差异。
3. 核对目标地址、上电模式、过流阈值和八个结果周期，再点击“配置为 BMS CAN1”。
4. 等待设备保存、重启和自动重读；以“已配置且一致”为完成信号。
5. 断开配置 PCAN，将 IVT 接入 F405 CAN1 后核对 `0x512..0x519`。

默认周期为电流 I 20 ms，其余通道 100 ms；F405 当前约 360 ms 判通道超时。当前版本的 IVT 配置连接固定使用 500 kbit/s。

### 2.6 两套风扇

整车 FanController 和 F405 电池箱风扇都使用统一 `CANB` 连接。手动、关闭、标定、保存和清除均要求真实 PCAN 500 kbit/s、逐次确认和匹配应答；手动或关闭租约为 1..60 秒，到期自动恢复温控，上位机不为普通手动操作续租。FanController 自动标定使用 60 秒硬失联租约并约每 5 秒续租；PDM 或风扇周期帧超过 1500 ms 时显示安全暂停，固件退出越限扫描并保持安全输出，直到上位机确认数据稳定、重发目标后才重做当前测点。过流、超温、供电档位确认变化、起转后停转和连接完全断开仍立即结束整轮。

页面显示实际占空比、转速、供电来源、限功率原因、故障和保存状态。周期遥测及查询得到的温控曲线、失联策略和标定上限在过期后保留最后回报，并同时显示“已过期”和年龄；旧故障不会继续显示为活动故障。自动标定开始条件、供电核对、温度、故障和 PDM 电流判断仍只使用新鲜帧。完整标定条件、扫描步骤、保存证据和验收记录只维护在 [`风扇标定与手动调试指南.md`](风扇标定与手动调试指南.md)。

### 2.7 MQTT 遥测故障

在“遥测故障”中配置 Broker、Topic、只读账号和 TLS。默认 Topic 为 `fsae/telemetry/v1`；拒绝 `#`、`+` 通配符，且没有发布接口。

页面优先解析 `battery_fault_code`，兼容旧 `fault_code`，并核对 `alarms` 里的告警明细与故障位是否一致。连续 3 秒没有有效数据时恢复“等待数据”；损坏或无已知字段的 Protobuf 只增加解析失败计数，不覆盖上一条有效记录。

连接参数保存在本机 WebView 存储中。当前 1883 连接为明文时，不应在共用电脑保存密码。协议权威源为 `vehicle-interfaces/telemetry/fsae_telemetry.proto`。

### 2.8 本地遥测模拟器

源码运行和两个平台的发布包都可从“工程工具 → 遥测数据模拟”启动两个兄弟仓库中 `local_sim2.py` 的上位机版本（Windows 安装版同样带这一页，pyserial 和 BMS 模拟帧定义随包发布；它不打开实体 CAN 的调试模拟通道）。模拟器固定生成 10 Hz 完整 `TelemetryFrame`，每 5 帧携带一次六模组明细。可同时选择以下输出：

- MQTT：默认发布到 `fsae/telemetry`；发布账号与密码必须同时填写或同时留空。密码只用于本次启动，不写入本机配置。
- 串口：8-N-1，默认 115200 bit/s；发送 Protobuf 原始字节，可追加 `0A`、`0D0A` 等十六进制包尾。
- PCAN：向选定的 500 kbit/s 测试 CAN1 持续注入 BMS 模拟帧。CAN 格式复用本仓库的 BMS 模拟器，不在遥测模块重复定义。

选择 PCAN 时必须确认通道接在测试总线上。不要连接实车或与实体 CAN1/CANB、台架、IVT 配置共用同一个 PCAN 通道。页面以“发送中”、各输出路径状态和递增计数作为启动完成信号；运行错误会留在页面，停止时关闭 MQTT、串口和 PCAN 句柄。

## 3. 接口与安全边界

| 连接              | 位率                     | 允许发送                         |
| ----------------- | ------------------------ | -------------------------------- |
| BMS CAN1          | 500 kbit/s               | F405 专用工具命令                |
| 统一 CANB         | 500 kbit/s               | 允许两套风扇专用命令及经确认的通用帧 |
| 台架 CAN1         | 500 kbit/s               | 六个从控模拟帧                   |
| IVT 配置 CAN1     | 500 kbit/s               | IVT 厂商配置命令                 |
| 本地遥测模拟 PCAN | 500 kbit/s               | BMS CAN1 模拟帧，仅测试总线      |

- 上位机解析只在 `canhost/decoders.py` 定义；精确帧格式由对应固件与 vehicle-interfaces 管理。
- F405 参数命令仅从 CAN1 发送，并要求新鲜状态、匹配协议版本、请求计数和应答。预充或高压闭合期间，是否执行仍由主控决定。
- 两套风扇命令仅从真实 CANB 500 kbit/s 发送。即使电池箱风扇由 F405 驱动，也不能从 BMS CAN1、模拟或回放下发。
- IVT 配置前必须确认总线上只有目标设备；模拟、回放和主监视连接不能执行配置。
- 每次通用发送都要确认物理总线、帧 ID、数据和周期；页面角色不代表实际接线。
- MQTT 只读订阅不占用 CAN 连接，也不提供远程命令。
- 本地遥测模拟器的 MQTT/串口输出不改变 CAN 连接；启用 PCAN 后会真实发送帧，必须使用独立测试通道。

## 4. 异常处理

| 现象                    | 检查                                                                       |
| ----------------------- | -------------------------------------------------------------------------- |
| 等待 CAN 数据           | 对应连接、PCAN 通道、位率、节点供电和接线                                  |
| 第二条连接失败          | CAN1 与 CANB 不能同时使用同一 PCAN 通道；在设置中分配两路或交换通道          |
| 未检测到 PCAN 通道      | 接入设备后点“刷新设备”；仍为空时检查 PEAK 驱动与 PCAN-Basic                 |
| 主控命令被拒绝          | BMS CAN1、主控状态、协议版本、状态新鲜度和应答原因                         |
| macOS 找不到 PCBUSB     | 安装 arm64 `libPCBUSB` 0.13+ 到 `/usr/local/lib`，先用 MacCAN Monitor 验证 |
| IVT 读取超时            | 设备供电、当前位率、总线唯一性和出厂/目标地址                              |
| 切换 IVT 位率后无 Alive | 用目标位率重连；失败时回原位率排查                                         |
| 风扇命令无应答          | 统一 CANB、500 kbit/s、控制器供电和对应应答帧                              |
| PDM 显示 INA226 离线    | 检查 PDM 供电与 I2C；定义见 PDM `Doc/CAN接口.md`                           |
| MQTT 拒绝或持续等待     | 只读凭据、Topic、Broker 桥接、接收计数和最近错误                           |
| MQTT 解析失败增加       | 核对发送端 Proto 与本仓库生成代码版本                                      |
| 遥测模拟器启动失败      | 查看页面错误；分别核对发布凭据、串口路径/权限、PCAN 驱动、通道占用和位率   |

## 5. 调试与验证

1. 先在低压、无高压输出条件下确认 PCAN 通道和位率。
2. 使用本地源码运行的调试模拟检查页面与解析；不要据此判断硬件正常。
3. 用本地遥测模拟器向测试 Broker 或环回串口发送，确认 10 Hz 总计数和 2 Hz 六模组帧；PCAN 输出只接低压测试总线。
4. 台架注入过压、欠压、温度、离线和断线，核对 F405 告警与页面。
5. 实车 CANB 逐卡核对原始帧和显示；IVT 配置后重新接入 CAN1 验证八通道。
6. 所有写操作同时保存请求、应答和周期回报；持久化配置需断电重启复核。

自动测试覆盖范围和未完成的实体检查见 [`../todo.md`](../todo.md)。F405 高压动作、故障复位和 Flash 日志按 BMS-MASTER-F405 的 `DOC/调试与台架测试.md` 执行。

## 6. 界面排版约定

界面提供深色和浅色两套赛车维修区主题，信息密度和确定的状态表达优先于装饰。点击侧栏 `CAN HOST` 右侧的太阳/月亮按钮可即时切换；选择同时保存在 WebView 本地存储和应用设置中，下次启动会在首帧前恢复，并让原生窗口底色与页面一致。默认仍为深色。浅色不是深色反相：画布使用冷灰工程纸面，测量表面接近白色，正常、过期、告警和故障分别使用适合亮背景的绿、琥珀和红色；两种主题中的状态含义完全相同。

所有排版和主题值只有一处权威：`canhost/web/styles.css` 顶部定义的变量表。页面样式必须使用语义变量，Canvas 趋势图从相同变量读取颜色，不能在页面脚本里另存一套只适用于某个主题的颜色。

| 变量组                         | 取值                    | 用途                                 |
| ------------------------------ | ----------------------- | ------------------------------------ |
| `--fs-unit`                    | 10.5px                  | 单位后缀、协议缩写、来源下标         |
| `--fs-label`                   | 11.5px                  | 字段标签、卡片标题右侧状态、说明文字 |
| `--fs-body`                    | 13px                    | 正文、卡片标题、按钮                 |
| `--fs-value`                   | 15px                    | 一般读数                             |
| `--fs-value-lg`                | 20px                    | 主读数、页面标题                     |
| `--fs-kpi`                     | 30px                    | 总览页首要读数                       |
| `--sp-1..5`                    | 4 / 8 / 12 / 16 / 24 px | 全部内边距与间距                     |
| `--r-flat` `--r-ctl` `--r-dot` | 0 / 2px / 50%           | 结构面、控件与标记、状态点           |

新增页面样式必须引用这些变量，不再直接写 `font-size`、`padding` 或 `border-radius` 数值。层级只有三层：外层面板是唯一的卡片层级，面板内不再嵌套带边框的卡片，子块用最浅表面或一条分隔线区分。读数与单位在同一基线内联显示，单位不单独占行。语义色只用于状态变化：正常状态保持安静，只有真正的告警、失效和超时使用高对比色；状态点不与文字重复表达同一件事。

读数、字段和动作各有固定写法，新页面沿用同一种：

| 用途       | 原语                        | 约定                                                                                                                                                                                                                                                                         |
| ---------- | --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 只读读数   | `.readout-grid` + `.cols-N` | 单元格之间只有 1px 缝隙；`--cols` 必须整除单元数，否则末行空单元会露出网格底色。结论、年龄、目标值放在贴右端的 `.cell-tail` 里，不另起盒子、不写进读数文字                                                                                                                   |
| 参数输入   | `.field-grid` + `.cols-N`   | 列数显式声明，同一行字段等宽；单位用 `em` 后缀，校验用 HTML5 属性，不再写字段说明                                                                                                                                                                                            |
| 动作按钮   | `.panel-foot`               | 一律另起一行右对齐；不与字段挤在同一行（同一行按内容排布会让同一行内的字段宽度随最长内容跳动，实测把“35”这类值裁掉）                                                                                                                                                         |
| 分组       | `.sub-head`                 | 标题在左、当前状态在右；机制说明进悬浮提示，不写进分组标题。标题左右不缩进，与下面第一行内容同一条左边界：容器自带内边距时（`.panel-body`）标题不再加缩进，只有 `.panel-body.flush` 这类无内边距容器才保留自带的 12px。标题下边框是这一组的起始线，与首行内容之间留 `--sp-2` |
| 表头与读数 | 网格行或 `<table>`          | 同一列的表头与读数同边对齐，本应用一律左对齐；只有整列都贴右端的列（如模组表的“状态”列）才把表头一起改为右对齐                                                                                                                                                               |

数据过期只标记整个读数单元：给单元格内部的 `<b>` 加 `data-stale` 不会命中任何配色规则。过期时读数退到次级灰、单位与尾部状态转告警色，尾部状态文字改成“已过期”或“上次目标”这类明确表述。

帧 ID、字节序和周期等协议信息放在标题的悬浮提示里（例如“来源 0x5A0 / 0x5A1 · 2 Hz”），界面上常驻的只有“数据是否可用”和“数据年龄”。操作界面不搬运固件说明，只保留读者可能真实误解的机制提示。

排版改动可用 `scripts/ui_preview.py` 在浏览器里复核（见 [`开发与发布.md`](开发与发布.md)）。
