# CAN 上位机与工具使用

本文说明车队 CAN 上位机（BITFSAE CAN HOST）各页面的职责、连接方法、接口边界和现场验证：BMS 监视四页、整车总览、整车风扇、MQTT 遥测故障、台架模拟从控和 IVT 配置。

帧格式的权威来源按接口分仓库：BMS 帧以 BMS-MASTER-F405 仓库 `DOC/CAN通信协议.md` 和固件 `App/bms_can_protocol.c` 为准；FanController 帧以 FanController 仓库 `Doc/风扇控制.md` 和 `Core/Src/fan_controller.c` 为准；PDM 帧以 PDM 仓库 `Doc/CAN接口.md` 和 `Core/Src/pdm_monitor.c` 为准；整车各节点的中央 DBC 登记在 vehicle-interfaces 仓库 `can/Vehicle_CanB.dbc`。两边不一致时以固件为准，同步修改本仓库实现、测试和 vehicle-interfaces。IVT 目标配置的完整表格在 BMS-MASTER-F405 仓库 `DOC/IVT能量计配置与CANB切换.md`。

上位机安装、源码运行和 Windows 发布见本仓库 [`README.md`](../README.md)。上位机进度、风险、验证和已完成变更只维护在本仓库 [`todo.md`](../todo.md)。

## 1. 工具职责和连接关系

### BMS 监视四页

运行总览、电芯与温度、故障与记录、参数与命令用于读取 F405 当前状态、查看单体和温度、查看故障、发送 F405 工具命令以及记录/回放 CAN 数据。主监视连接可选 CAN1 或 CANB；CANB 上没有 138 串电压和 48 路温度的原始从控报文，相关区域显示“等待数据”。

### 整车总览与整车风扇

整车总览在一个独立 CANB 连接上集中显示整车侧节点：SOP 限功率（0x4A0/0x4A3/0x4A4）、BMS 整车镜像（0x4B0/0x4B1）、赛会能量计（0x521/0x522/0x526/0x528）、PDM 低压两侧（0x5A0/0x5A1）、ECU 四轮调试帧（0x502/0x505–0x509）和轮胎温度（0x071–0x074）。自有 IVT-S 八通道位于 CAN1，由 BMS 主监视和 IVT 配置页处理。

整车风扇页面共用同一条整车连接，查看 FanController 的三路转速、两路占空比、温度与故障，并发送模式、自动温控曲线和失联策略命令。命令带 CRC-8 并等待 FanController 按操作码和序号应答。

整车连接与 BMS 主监视连接互相独立：可以主监视接 CAN1 调 F405 参数，同时整车连接接 CANB 看低压和高压数据，底部快捷栏同时显示两条连接的常用值。

### 台架模拟从控

台架模拟从控用于给 F405 的 CAN1 提供六个从控的测试报文，验证接收、完整性判断、告警和从控离线处理。它复用 `cli/pcan_bms_bench.py` 的模型和命令。页面只负责连接、发送和显示状态，不改变 F405 Flash，也不伪造 IVT、充电机或 IMD 数据。

### IVT 配置

IVT 配置用于首次安装或维护真实 IVT-S。它使用独立 PCAN 连接读取配置，判断当前设备是否已经与 CAN1/500 kbit/s 目标一致，并在需要时完整写入配置或切换 250/500 kbit/s 位率。它与 BMS 主监视连接互不影响。

### MQTT 遥测故障

遥测故障页默认订阅 Broker 的干净 Topic `fsae/telemetry/v1`，解码 CRC 已通过的 `TelemetryFrame`，并显示 BMS 32 位故障字、当前状态、告警等级、`alarms` 列表和本次订阅内的故障变化记录。MQTT 使用第五条独立、只读连接，不占用 PCAN，不切换 BMS、整车、台架或 IVT 的连接模式，也没有发布或远程命令入口。

台架和 IVT 配置收在左侧“工程工具”折叠项中，这两页隐藏底部状态栏以获得最大工作区。日常监视不会自动打开这些页面。

## 2. 总线用途和安全边界

| 总线选项 | 位率 | 用途 | 上位机发送范围 |
|---|---:|---|---|
| CAN1 | 500 kbit/s | 从控原始采样、主控周期状态、F405 工具命令与应答 | F405 工具命令；台架页发送从控帧 |
| CAN1 | 500 kbit/s | BMS 从控、F405、自有 IVT-S 和工具 | F405 工具命令；独立连接下的 IVT 厂商配置命令 |
| CANB | 500 kbit/s | BMS 状态/故障/告警、SOP、赛会能量计、PDM、两套风扇、ECU、胎温 | FanController `0x5A4`、电池箱风扇 `0x5AB` |
| CANB Legacy | 250 kbit/s | Legacy 充电机和 BMS 状态/故障/告警 | FanController `0x5A4`、电池箱风扇 `0x5AB`；只在节点同为250 kbit/s时使用 |

- 接口定义以 vehicle-interfaces 的 DBC 做团队中央登记，以各固件仓库的实现为最终依据；本仓库解析代码（`canhost/decoders.py`）与测试和两边保持同步。
- F405 工具命令只从 CAN1 发送。整车连接是只读监视加 FanController 命令；BMS、ECU、Chroma 和 Legacy 报文按各自接收路径处理。
- IVT 配置使用独立的 Command/Response ID。配置前先确认 PCAN 位率与 IVT 当前位率一致，并确认配置总线上只有目标 IVT；正式接入 F405 前切到 500 kbit/s。
- 台架模拟从控工具只在自己的 CAN1 连接上发送六个从控帧；它不发送 IVT 结果帧。模拟数据、历史回放和 BMS 主监视连接都不能执行 IVT 配置。
- 阈值、告警开关、充电请求、电流方向、充电机类型、RTC、Flash 日志清除、故障复位和全部风扇写命令都要求逐次确认。电池箱内风扇由 F405 主控驱动，CAN1 `0x186250F4/0x186E50F4` 用于监视，CANB `0x5AA..0x5AD` 用于限时查询、远程控制和功率标定。
- 整车风扇命令发给 CANB 上的 FanController；电池箱风扇命令发给同一总线上的 F405。两者的手动/关闭模式都必须带 1..60 秒有效时间，到期自动回温控。需要保持手动转速时由操作者按短于有效时间的间隔重发，上位机不做自动续发。
- 所有 F405 工具命令使用统一扩展 ID `0x18A050F5` 和协议版本 5；Byte0 高 4 位是版本、低 4 位是操作码，Byte1 是请求计数，固定 DLC=8。除 RTC 外均核对请求计数、命令码和主控 `0x18A650F4` 统一应答。
- 配置类命令只在自检、待机或故障保持态处理。预充和高压闭合期间由主控拒绝；充电机类型还要求退出充电模式且高压状态机空闲。
- 故障复位仍由主控检查实时告警和实体 HV_ACC 上高压请求是否已释放。上位机只发送请求，不替代主控的安全判断。
- 单体过压阈值默认 4190mV。上位机输入框统一允许 3011..4500mV，但只有 Debug-Bringup 固件接受 4191..4500mV；该值由 F405 保存到 Flash，重新上电后仍按保存值生效。正式 Debug、Release 和 Release-Legacy 固件最高接受 4190mV。
- 告警开关页面按整组（当前 23 位）写入。关闭告警开关只关闭保护动作，不关闭检测：原始告警、故障码和告警等级明细仍持续上报。基础安全保护（单体电压/温度、采样线断线、包电压、持续过流、总压一致性、SOC、LV1/LV2 总开关）在 Debug-Bringup 可关闭；Debug、Release 和 Release-Legacy 只允许关闭压差/温差、辅助诊断、CAN 运行诊断和蜂鸣器。电流传感器异常、IVT 包电压失联、从控未就绪和从控完全离线是 HV_ON 动作开关，只在高压保持阶段影响动作。
- MQTT 遥测连接只订阅明确 Topic，拒绝 `#` 和 `+` 通配符，不提供 publish。Broker、端口、Topic、用户名和密码保存在本机页面设置中，换电脑或清空浏览器数据后需重新填写；后端只在建立连接时使用密码，日志和状态快照不含密码。

## 3. BMS 监视使用

1. 点击底部“BMS 未连接”（或已连接状态按钮）。
2. 在弹出的“BMS 主连接”弹窗中选择监视总线和 PCAN 通道。
   - 源码运行时会额外显示 `内置模拟数据 · CAN1 / 开发测试`，用于没有实体 PCAN 时的界面和协议开发；Windows 发布版不提供该项。
   - `CAN1 · F405 主控 / 从控 / 工具`：查看 138 串、48 路温度、F405 状态和发送 F405 工具命令。
   - `CAN1 · F405 / 从控 / IVT / 工具 · 500 kbit/s`：查看 BMS 原始输入、主控状态和自有 IVT。
   - `CANB · ECU / Chroma · 500 kbit/s`：查看 BMS 整车镜像、SOP 和 500 kbit/s 充电链路。
   - `CANB · Legacy · 250 kbit/s`：查看 Legacy 固定 250 kbit/s 链路。
3. 连接后先看“运行总览”的状态机、告警和关键电气量；需要定位时进入“电芯与温度”“故障与记录”或“CAN 监视器”。电芯页按 CAN1 从控原始帧显示：`0xFFFF`/`0xFF` 只让对应格子显示「断」，同帧其他串仍显示数值；过低或过高的模拟量按数值显示，并由主控阈值标成欠压/过压。主控故障名「电压采样线断开」表示采样线开路，伴随「从控数据未就绪」是正常的。
4. 需要改 F405 参数时进入“参数与命令”。界面会检查 CAN1、主控状态和状态帧新鲜度，每次写入都需要再次确认。PCAN 发送成功不代表主控已经接受，最终以主控应答和周期回报为准。

主控工具命令只从 CAN1 发送。CANB 连接用于读取 CANB 数据，不用于发送 F405 主控配置命令。数据无效、报文缺失或状态帧超时时，页面显示“等待数据”，不使用 0 或旧值冒充当前结果。

RTC 校时按钮旁的状态在本次连接内持续显示最近一次校时应答和主控读回的时间；尚未校时时按主控周期上报的 RTC 有效性显示“主控 RTC 有效”或“RTC 未校时”。校时写入的是上位机本地时间，主控 Flash 日志时间戳与此同一口径。

“故障码变化记录”和 CAN 监视器的时间列使用上位机收到帧时的本机时间，不使用 PCAN 适配器内部计数；CSV 和 `.bmslog` 记录、回放显示同为这一口径。主控 Flash 故障日志的时间来自主控 RTC，与上位机接收时间无关。

## 4. 整车总览

### 连接

1. 点击底部“整车未连接”（或已连接状态按钮）。
2. 在弹出的“整车 CANB 连接”弹窗中选择 PCAN 通道和位率（整车 CANB 为 500 kbit/s），点击“连接”。
3. 源码运行时另有 `内置模拟数据 · CANB`，用于无实体 PCAN 时的整车页面开发；Windows 发布版不提供该项。
4. 底部状态栏的“整车连接”按钮显示实时通道与位率，再次点击可查看或断开连接。

### 页面内容与判定

| 卡片 | 数据来源 | 判定 |
|---|---|---|
| SOP 限功率 | `0x4A0` 限值 + `0x4A3` 状态 + `0x4A4` ECU 确认 | 实车 BMS 只在放电模式已接通高压时发送；配对 CRC 校验失败会标红；ECU 确认区分“已采用/未确认/ECU 故障” |
| BMS 整车镜像 | `0x4B0` 包状态 + `0x4B1` 故障 | 电压/电流/SOC 各自带有效位，无效显示“等待数据” |
| 自有 IVT-S | `0x512..0x519`（小端） | 每通道独立新鲜度；结果状态非 0 标“结果异常” |
| 赛会能量计 | `0x521/0x522/0x526/0x528`（大端） | 功率/能量两帧设备可能不发送，未收到显示“未发送” |
| PDM 低压配电 | `0x5A0` 总线侧 + `0x5A1` 电池侧 | 四字段全无效值判该路 INA226 离线；累计电量为上电累计，655.36 Wh 回绕 |
| ECU 四轮状态 | `0x502/0x505..0x509` | 扭矩 %Mn、转速、电机/逆变器/IGBT 温度按 FL/FR/RL/RR 显示；就绪/使能/故障按轮汇总 |
| 轮胎温度 | `0x071..0x074` | 每帧 4 测点（整数 + 0.01 °C 小数）；帧与轮位的对应关系待实物确认，按帧 ID 分组显示 |
| 高压/低压趋势 | 0x4B0 与 PDM 采样 | 左轴高压电压、右轴低压电压，图例同时显示两路电流 |

### 常看值快捷栏

所有非工具页在底部状态栏上方常驻一行常看值：低压电压/电流/功率（PDM 总线侧）、高压电压/电流、SOC、SOP 放电/充电功率限值、风扇最高转速。高压和 SOC 优先取 BMS 主监视连接，主连接无数据时回退整车连接的 `0x4B0`；低压、SOP 和风扇来自整车连接。任一来源无数据时该格显示“等待”，不用 0 冒充。调 F405 参数（CAN1）的同时可以在这里看 CANB 上的低压值。

### CAN 监视器数据源

CAN 监视器工具栏新增“主连接 / 整车连接”切换：主连接看 BMS 监视通道的原始帧，整车连接看 CANB 整车通道的原始帧（含新节点帧名，如 PDM `0x5A0/0x5A1`、ECU `0x502..0x509`、胎温 `0x071..0x074`）。筛选、暂停和行数限制对当前数据源生效。

## 5. 台架模拟从控

### 连接和启动

1. 展开左侧“工程工具”，进入“台架模拟从控”。
2. 选择连接 F405 CAN1 的 PCAN 通道，点击“连接”。页面固定使用 500 kbit/s。
3. 看到六个从控状态后，再开始注入场景。主上位机需要同时监视 F405 时，可以在另一个主监视连接中打开同一 CAN1；如果 PCAN 驱动拒绝第二个句柄，按提示释放占用或使用另一个 PCAN 通道。

### 页面会发送什么

台架启动后按脚本周期发送：

- 六个从控的 36 帧电压数据，合计 138 串；
- 六个从控的 6 帧温度数据，合计 48 路；
- 不发送 IVT `0x512..0x519`、充电机反馈或 IMD 报文。

六个从控默认在线，电芯和温度使用脚本中的默认值。页面下方的六个状态格用于确认从控在线情况和默认测量值。

### 注入场景

快速按钮用于常用测试。命令框接受脚本的原命令格式，例如：

```text
cell 1 3900
temp 1 40
slave 2 online off
scenario openwire on 1
```

开始下一组测试前点击“恢复默认”。需要验证 F405 真实 IVT、充电机、IMD 或 CANB 报文时，使用真实设备或对应独立工具，不在本页面伪造。

## 6. IVT 配置

### 连接前准备

1. 断开其他节点，只把 PCAN 和目标 IVT-S 接到配置总线。
2. 总线上只保留目标 IVT 和 PCAN，暂时移除其他会响应 IVT 命令的节点。
3. 在页面选择 PCAN 通道和 IVT 当前位率。第一次读取出厂设备通常使用 500 kbit/s；如果设备当前用于旧 Legacy 充电机，按设备当前实际位率选择 250 kbit/s。
4. 点击“连接”。PCAN 位率必须与 IVT 当前位率一致，否则不会有有效应答。

### 先读取，再决定是否配置

点击“读取并核对”。页面会先尝试出厂地址 `Command 0x411 / Response 0x511`，再尝试 BMS 目标地址 `0x410 / 0x51A`，随后读取设备信息、当前/上电模式、8 个通道、结果帧地址和正负过流阈值。

核对结果的含义：

| 页面结果 | 含义 | 下一步 |
|---|---|---|
| 已配置且一致 | 当前配置与 F405 CAN1 目标全部一致 | 可以断开配置通道，接入 F405 验证结果帧 |
| 未配置 | 读取到出厂通道、地址和关闭过流阈值 | 首次接入 F405 前执行一次 BMS CAN1 配置 |
| 配置不符 | 只有部分项目一致，或存在被改过的参数 | 展开逐通道核对，确认后再配置 |

页面主区域只显示现场需要的结果。逐通道周期、格式和差异放在“查看逐通道核对”中；当前 Command/Response ID 和过流核对值放在“高级”中，通常不需要修改。

### 配置为 BMS CAN1

当设备是首次安装、核对结果为“配置不符”，或需要调整通道周期时：

1. 确认总线仍只有目标 IVT，且 PCAN 位率与 IVT 当前位率一致。
2. 如有需要，在“高级”中填写目标上电模式和过流阈值；过流值为 0 表示关闭。
3. 在“结果通道周期”中填写 I、U1、U2、U3、T、W、As、Wh 的发送周期。页面实时显示八通道合计帧率；默认 I 为 20 ms，其余为 100 ms。“载入读回周期”可把设备当前值填入输入框，再在当前值基础上调整。F405 当前约 360 ms 判通道超时，调整周期时要同步核对固件新鲜度窗口。
4. 确认当前为 500 kbit/s，点击“配置为 BMS CAN1”，在确认窗口核对通道、目标地址和八个周期后确认。
5. 页面会停止 IVT，写入 BMS 目标配置，保存并重启 IVT，然后自动等待 Alive 和重新读取。
6. 看到“已配置且一致”后，断开配置 PCAN，按 BMS-MASTER-F405 仓库 `DOC/IVT能量计配置与CANB切换.md` 的步骤接入 F405 CAN1。

页面会先要求完成“读取并核对”：读回前配置按钮保持禁用；如果读回结果与当前输入目标一致，配置按钮保持禁用。修改任一通道周期后按钮重新启用，避免无变化时重复写入。

BMS 目标的现场摘要为：结果帧 `0x512..0x519`，通道格式 `0x42`（小端、周期发送、正常符号、报错位关闭），Command `0x410`，Response `0x51A`。页面默认周期为电流 I 20 ms、其余通道 100 ms，现场可以直接编辑并随完整配置写入；每个通道的完整字段见 IVT 文档。

### 旧 Legacy 充电机的位率切换

“旧充电机过渡”只改变 IVT 的 CAN 位率，不改变结果通道和 CAN ID：

- 旧 Legacy 充电机链路需要 250 kbit/s 时，点击“切到 250 kbit/s”；
- 回到 F405 当前 CAN1/500 kbit/s 链路前，点击“切到 500 kbit/s”。

点击后 IVT 会重启，上位机会关闭当前 PCAN、按目标位率重新打开并等待 Alive。切换前后的连接位率必须与设备实际位率匹配。Legacy 固定变体的安装位率由整车配置决定，运行中不反复切换。

## 7. 整车风扇

### 连接和查看状态

1. 整车风扇页使用整车连接（与整车总览共用）。点击底部“整车未连接”（或已连接状态按钮），在弹出的“整车 CANB 连接”弹窗中选择 PCAN 通道和位率后连接；也可以先在整车总览页连接，再进入本页。
2. 连接后页面解析 FanController 和 F405 电池箱风扇报文：
   - `0x5A2`（100 ms）：三路实际转速与两路当前实测占空比；
   - `0x5A3`（500 ms）：目标占空比、当前模式、最高电机/控制器温度、温度输入有效位和 8 个故障位；
   - `0x5A8`（100 ms）：供电状态机（低压电池 / DCDC接管中 / DCDC就绪 / 功率受限 / 数据故障）、限功率原因、电流预算（A）与预测总线电流（A）。
   - `0x5A9/0x5AE`：整车风扇标定会话，以及低压电池/DCDC两档保存上限；未标定时两档均为15%。
   - `0x5AA..0x5AD`：F405电池箱风扇状态、应答、35W Chroma/70W高压两档上限和保存状态。该组帧只在查询或活动会话窗口内发送。
3. 帧超时或温度源失联时显示“等待数据”或“失联”，不用 0 冒充读数。

### 发送命令

命令使用标准帧 `0x5A4`（DLC=8，字节 7 为 CRC-8/SAE-J1850），页面在确认窗口核对通道、位率和参数后发送，并等待 `0x5A5` 按操作码和序号应答；1 秒无应答或结果非成功时明确报错。可用命令：

| 操作 | 操作码 | 内容 | 限制 |
|---|---|---|---|
| 模式与目标占空比 | `0x01` | 自动 / 手动 / 关闭 | 手动/关闭带 1..60 秒有效时间，到期自动回自动；关闭模式两路必须为 0 |
| 回路1温控曲线 | `0x02` | 电机水套曲线五个参数 | 关闭 < 启动 < 全速 ≤ 150 ℃，占空比和速度 10..100 |
| 回路2温控曲线 | `0x06` | 逆变器/IGBT曲线五个参数 | 关闭 < 启动 < 全速 ≤ 150 ℃，占空比和速度 10..100 |
| 失联策略 | `0x03` | 策略、两路保底占空比、保持时间、下降速度 | 策略 0..2，保底 0..100%，保持 0..30 秒，下降 10..100%/s |
| 恢复默认策略 | `0x04` | 曲线 35/40/60 ℃、固定保底 50%/50%、保持 5 s | 同时回到自动模式 |
| 查询当前策略 | `0x05` | 触发回报 `0x5A6` 与 `0x5A7` | 无参数 |
| 标定会话控制 | `0x08` | 启动/续约/停止/确认DCDC就绪/保存/清除 | 低压电池或DCDC稳定档位均可分别扫频；带1..60秒租约与过流/超温保护。Action=5保存两档上限，Action=6恢复未标定15% |

温控曲线和失联策略只保存在 RAM 中，FanController 复位后恢复默认。写入成功后页面用回报值刷新输入框；修改过输入框后以页面值为准，直到发送成功或重新查询。

### 台架功率标定工作台

页面提供自动阶梯扫频标定工作台：
1. **安全前置检查**：必须满足 PCAN 在 CANB 上、PDM 总线遥测正常、电机温度 < 70 ℃、无风扇停转故障，并且固件供电状态与所选低压电池或DCDC档位一致；DCDC档还要求PDM双路实测判据连续稳定3秒；
2. **基准测量**：自动测量 0% 占空比下的低压总线静态功耗（$V_{\text{base}}, I_{\text{base}}, P_{\text{base}}$）；
3. **阶梯扫频**：按预设步长（含 5/8/10/12/15% 低占空比点，0%..100%）阶梯调节目标通道（PWM1 / PWM2），等待稳态并计算增量 $\Delta I$ (A) 与 $\Delta P$ (W)；
4. **实时安全监控**：在扫频全过程中若检测到 PDM、0x5A2、0x5A3、0x5A8 任一超时，或供电档位变化、总线过流、超温、风扇停转，立即触发紧急中止；
5. **数据导出**：CSV 与 JSON 保存实际扫描参数、每条记录的关联基线和原始采样，便于复核拟合。

分别扫完低压电池和DCDC档后，在页面输入根据记录选定的两档最大安全占空比并保存。收到`0x5AE`已标定位且数值一致后断电重启，再查询确认Flash加载结果。

### 电池箱风扇控制和标定

电池箱风扇区域先发送查询，随后读取`0x5AA/0x5AD`。普通手动命令受当前55%或已标定上限约束。标定只允许在非Chroma的稳定高压/DCDC状态：先以0%记录PDM总线功率基线，再逐档发送开始/更新并记录RPM和扣除基线后的功率；到达35W、70W时分别选择不超过预算的最大稳定占空比。停止有效会话后提交两个上限。`0x5AD`保存等待位清零表示Flash写入完成，断电重启后必须再次查询复核。

### 应答记录

页面下方显示最近的 `0x5A5` 应答：操作码、序号、结果、当前模式、失联策略和四路占空比。手动/关闭模式到期自动回自动时，FanController 会主动补发一条“模式超时，已回到自动”的应答。

## 8. MQTT 遥测故障

### 连接

1. 进入左侧“遥测故障”，点击“配置订阅”。
2. 现网默认 Broker 为 `bitfsae.com:1883`，Topic 为 `fsae/telemetry/v1`。当前 Mosquitto ACL 中可读该 Topic 的账号是 `telegraf`，密码在遥测服务器 `/home/ubuntu/fsae_project/.env` 的 `MQTT_TELEGRAF_PASSWORD`，按车队凭据流程获取，不要写入仓库或聊天记录。
3. 填入只读账号和密码后点击“订阅”。连接成功后状态显示“遥测订阅中”，接收计数持续增加。
4. 当前现网 `1883` 是明文 MQTT，TLS 开关保持关闭；它不会加密账号、密码和 Payload。只有 Broker 已部署 MQTT TLS 后，才启用 TLS 并填写对应端口。

Broker、端口、Topic、用户名、密码和 TLS 选项会保存在本机页面设置，下次打开订阅设置时自动填入，无需重复输入。密码以明文保存在本机 WebView 存储中，不要在共用电脑上保存；后端日志和状态快照不含密码。

### 故障码解析

- 当前 G473 网关同时填充旧顶层 `fault_code` 和 BMS 专用 `battery_fault_code`。上位机优先使用 `battery_fault_code`；旧发送端只填 `fault_code` 时自动兼容；两个字段同时非零且不一致时明确提示。
- 32 位故障含义复用 F405 BMS 统一故障字定义，与 CAN 主监视“故障与记录”页相同。置位项按 `BIT 0..31` 显示，不另定义遥测专用故障表。
- `TelemetryFrame.alarms` 是 32 位 BMS 故障字的展开列表；`alarm_id=0..31` 对应同名 bit，一级故障显示为致命，二级告警显示为警告。网关可以留空 `message`，上位机会按 ID 补中文名称。
- 页面同时计算告警明细的 bit 位图并与 `battery_fault_code` 比较。两者不一致时显示“告警明细与故障字不一致”，便于区分上游时序或版本问题。
- 连续 3 秒没有收到新 Payload 时，当前故障码、状态和告警改为“等待数据”，不继续显示旧值。即使 MQTT 仍在收包，若网关没有携带 presence 明确的 `bms_telemetry.battery_state/battery_alarm_level`，零故障字也按“等待数据”处理，不能把上游 BMS 失联误判为正常；非零故障字仍作为可操作故障显示。本次 MQTT 会话的故障变化记录保留，BMS 来源失效产生的零值不会记录成“故障清除”。
- 每条 Payload 必须能解码为包含已知字段的 `TelemetryFrame`；空 Payload、损坏的 Protobuf 或没有已知字段的数据计入“解析失败”，不会覆盖最后一条有效数据。

遥测机器可读协议以同级 `vehicle-interfaces/telemetry/fsae_telemetry.proto` 为权威源。G473 的固件、服务器和 Python 生成副本在 `CANRS485_G473/REFERENCE/protobuf-master`；协议变化后需要重新生成并同步本仓库 `canhost/telemetry/fsae_telemetry_pb2.py`，再更新解析测试。

## 9. 常见提示和处理

| 提示或现象 | 处理 |
|---|---|
| 等待 CAN 数据 | 检查对应连接、PCAN 通道和位率；数据无效时页面保持“等待数据”，不会用 0 或旧值代替 |
| 整车页某卡片整卡“等待数据” | 该节点没有上电或不在 CANB 上；赛会能量计的功率/能量两帧未发送属正常，显示“未发送” |
| PDM 某侧显示“INA226 离线” | 该路 INA226 无响应（四字段全无效值）；检查 PDM 供电与 I2C，见 PDM 仓库 `Doc/CAN接口.md` |
| 台架连接失败 | 检查 PEAK 驱动、PCAN 通道是否被占用，以及通道是否确实接到 F405 CAN1 |
| IVT 读取超时 | 确认 IVT 供电、当前位率和总线接线；出厂设备用 0x411/0x511，已配置设备让页面自动探测或在高级中填写当前地址 |
| IVT 配置不符 | 查看逐通道核对；确认设备确实是要接入本 F405 的 IVT 后再重新配置 |
| 切换位率后没有 Alive | 用目标位率重新连接；仍无响应时回到原位率检查设备和接线 |
| 整车风扇命令无应答 | 确认 FanController 供电、CANB 接线和位率；1 秒无 `0x5A5` 时命令不会重发 |
| 整车风扇命令被拒绝 | 查看应答记录中的结果：参数错误按命令表核对范围；CRC/长度错误一般只在总线干扰或固件不一致时出现 |
| 遥测连接被拒绝 | 核对只读 MQTT 账号与密码；现网关闭匿名访问，`vehicle_gateway` 只有发布权限，不能用于订阅遥测 |
| 遥测订阅中但一直等待数据 | 确认服务器桥正在从 raw `fsae/telemetry` 发布 clean `fsae/telemetry/v1`；检查接收计数、解析失败数和最近错误 |
| 遥测解析失败持续增加 | 对照权威 Proto 检查发送端与上位机生成代码是否同步；损坏 Payload 不会替换最后一条有效帧 |
| 第二个独立连接失败 | 可能是 PCAN 驱动不允许同一通道同时打开多个句柄；先断开占用连接或换用另一个 PCAN 通道 |
| 主控命令被拒绝 | 查看“参数与命令”的主控状态、告警和应答原因；预充或高压闭合期间不要反复发送 |

故障、数据失效和状态帧超时使用不同的醒目状态。正常状态保持安静；看到“等待数据”时先处理连接或报文问题，不要按测量值为 0 继续判断车辆状态。

## 10. 验证顺序

### 软件内更新

Windows 发布版左下角的版本信息是“软件内更新”入口。程序启动时自动检查一次 `BITFSAE/can-host` 的正式 Release，发现新版本时版本入口会出现提示；不会自动下载或安装。也可点击左下角版本信息手动检查、下载和安装：

1. 打开“软件内更新”窗口；窗口会先刷新当前状态，尚未检查时自动发起一次检查。点击“检查更新”可随时重新检查；展开“更新选项与私有仓库设置”后，勾选“包含预发布版（Pre-release）”可检查带有 `-rc1` 等后缀的预发布。
2. 确认版本对比和版本说明后点击“下载并校验”，程序下载 ZIP 与对应 `.sha256`，校验 SHA256 并验证 ZIP 只包含 `BITFSAE_CAN_Host/` 目录（拒绝绝对路径、`..` 和符号链接）。
3. 校验通过后点击“重启并安装”：当前应用退出，隐藏 PowerShell 助手等待旧进程结束，将旧目录备份为 `.old-<时间戳>`，移入新目录并重新启动；新版本启动失败时自动恢复旧目录。旧版本备份保存在安装目录的上一级目录，名字形如 `BITFSAE_CAN_Host.old-<时间戳>`；安装成功后助手只保留最近一份旧备份用于手动回退，更早的备份会自动清理。确认新版本正常后，可手动关闭上位机，在资源管理器中删除这份 `BITFSAE_CAN_Host.old-*` 目录以释放空间。
4. 仓库为公开时无需任何凭据；仓库为私有时在“更新选项与私有仓库设置”中保存只读 GitHub PAT（至少 `contents:read`），令牌只保存在本机 `%APPDATA%\BITFSAE\CAN Host\settings.json`，不返回前端、不写入日志。
5. 源码运行只能检查更新，不能替换安装目录。安装按钮会保持不可用；安装失败或新版本启动失败时旧目录保持或自动恢复，可查看 `%TEMP%\canhost-update-*` 下的 `install-helper.log`；该临时目录由更新助手维护，下一次下载前会自动清理。

发布者操作与 CI 生成附件见 [`../README.md`](../README.md) 的“CI 自动构建与发布”和“软件内更新”两节。

### 软件和界面

1. 源码运行上位机，确认 BMS 四页、整车两页、CAN 监视器、遥测故障页和工程工具折叠项都能打开。
2. 主监视连接用内置模拟数据走一遍 BMS 页面；整车连接用内置模拟数据走一遍整车总览和风扇页，确认所有卡片有数、快捷栏九格有值。

4. 用真实 IVT 完成“读取—分类—配置—重读”流程，确认显示“已配置且一致”。
5. 连接真实 FanController，确认状态与诊断显示、五种命令的应答结果，以及手动模式到期自动回自动的补发应答。
6. 用只读 MQTT 账号订阅真实 Broker，再用 G473 或 `local_sim2.py` 发布正常、故障进入、故障切换和清除帧，核对故障位名称、变化记录、断流 3 秒后的等待状态和损坏 Payload 计数。

### 实体联调

1. 先在低压、无高压输出条件下验证 PCAN 通道和位率。
2. 整车连接接实车 CANB，逐卡确认 SOP、0x4B0、PDM、ECU、胎温有真实数据。
3. 配置 IVT 后断开配置 PCAN，再接入 F405 CAN1，检查 `0x512..0x519`、IVT 离线告警和 U1 与 BMS 包电压一致性。
4. 旧 Legacy 链路分别验证 250 kbit/s 和回切 500 kbit/s 的 Alive、结果帧周期和 F405 接收状态。
5. F405 工具命令、故障复位、Flash 日志和高压动作按 BMS-MASTER-F405 仓库 `DOC/调试与台架测试.md` 执行；本文不重复固件内部判定规则。
