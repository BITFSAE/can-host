# 风扇标定与手动调试指南

本文说明两套风扇的功率标定和手动调试，涉及 `can-host`、`FanController`、`BMS_MASTER_F405` 和 `PDM` 四个仓库。接口权威位置见[文档索引](README.md)。

所有风扇写命令只允许从真实 PCAN 的整车 CANB 发出；模拟、回放、`CAN1` 和 `BMS CANB` 都是只读路径，后端会拦下写入。

## 1. 两套风扇系统

车队有两套互不相干的风扇系统，控制器、接线和 CAN 接口都不同，帧 ID 也不重叠。动手前先确认自己要操作的是哪一套。

| 系统                 | 控制器                                | 驱动的风扇                                        | CAN 帧                                                                                                         | 标定内容                                          | 保存位置                                                             |
| -------------------- | ------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------- |
| 整车水箱与控制器散热 | FanController（STM32F103C8T6）        | PWM1：2×4114N/2H4PU；PWM2：1×4114N/2H6P           | CANB 命令 `0x5A4`、应答 `0x5A5`、状态与诊断 `0x5A2..0x5A9`、上限 `0x5AE`                                       | 低压电池档与 DCDC 档各自的最大 PWM 上限（%）      | 主 Flash 最后两个 1KB 页（`0x0800F800` / `0x0800FC00`）              |
| 电池箱内部风扇       | BMS_MASTER_F405 主控（STM32F405RGT6） | 1× 电池箱风扇（当前资料为 ebm-papst 3214 J/2H4P） | CANB 命令 `0x5AB`、应答 `0x5AC`、状态 `0x5AA`、标定与上限 `0x5AD`；CAN1 另有监视帧 `0x186250F4` / `0x186E50F4` | Chroma 充电 35W 上限与整车高压/DCDC 70W 上限（%） | 外部 Flash Sector8 的独立记录区（记录标识 `0x464E`、版本 1、3 字节） |

### 1.1 连接角色

写命令只有一条路径：底部“整车 CANB”加真实 PCAN，位率 500 kbit/s。`CAN1`（BMS 主监视）和 `BMS CANB`（只读镜像）供监视用，不能发风扇命令。

电池箱风扇虽然由 F405 驱动，命令同样从整车 CANB 发 `0x5AB`，不要改从 BMS CANB 发：两者是不同的服务，帧定义和接收方都不一样。

250 kbit/s 只属于旧充电机链路，风扇标定不要选它，FanController 和 PDM 都在 500 kbit/s 的 CANB 上。

模拟连接只用于界面开发。即使界面看起来可用，标定、手动和提交按钮在模拟连接下都会被后端拦下。

### 1.2 PDM 测量与电流方向

PDM 每 100 ms 依次发送两帧，两帧格式相同：

| CAN ID  | 内容                                       | 在标定中的作用                                                 |
| ------- | ------------------------------------------ | -------------------------------------------------------------- |
| `0x5A0` | OR-ing 汇合后的低压总线电压/电流/功率/电量 | 整车低压总负载，标定和功率保护的主依据                         |
| `0x5A1` | 低压电池支路电压/电流/功率/电量            | 判断 DCDC 是否接管、电池是否仍在放电，决定当前该用哪个电流预算 |

电流方向已实测确认：正电流是放电（负载消耗），负电流是充电。只有四个字段同时为无效值时，才表示该路 INA226 离线；单个字段越界时，固件按其余有效字段继续判断。

两个预算（8.0 A 和 18.0 A）限制的是 `0x5A0` 的总线总电流，其中包含整车背景负载。

## 2. 标定的作用和测量内容

固件不保存转速曲线，只保存每个供电档位的占空比上限。温控负责算出“该用多少占空比”，标定负责给出“当前供电最多允许多少占空比”，实际输出不会超过这两者中的上限。

FanController 的处理顺序是：温控算出理论占空比，按供电档位上限封顶，再按电流预算削减，最后经启动脉冲和升降斜率输出。固件里用于预测电流的功率表仍按 30/50/70/100% 给临时值，反映不了实际线束和风扇，所以每种供电条件下的安全占空比只能在车上用 PDM 实测。标定结果用于封顶，不会更新那张预测表。

F405 电池箱风扇的自动温控和普通手动命令都按当前供电来源的上限封顶，未标定时按 55%。只有高压/DCDC 标定过程可以临时越过上限扫频，并且仍受固件安全看门狗和上位机总线电流保护约束。

一次标定采集这些数据：

- 每个阶梯点的稳态 PWM 与总线电流、功率；
- 扣除邻近 0% 基线后的增量电流和增量功率。基线里含整车背景负载，扣掉之后剩下的才是风扇本身；
- 三路 RPM 是否真正起转，用于识别停转、卡滞和 TACH 故障；
- FanController 要分别扫低压电池档与 DCDC 档，因为两档的电流预算不同；
- F405 只扫一次高压/DCDC，用同一条曲线推导 35W 和 70W 上限。Chroma 充电时的电压和线束压降与 DCDC 不同，首次接入必须用 PDM 复测，不能直接沿用 DCDC 曲线。

推荐上限是上位机算出的建议值，只显示在页面上，提交并写入固件后才生效。写入是否成功以命令应答和状态帧为准：界面显示成功不等于已经保存到 Flash。

## 3. 扫频中两套系统相同的部分

### 3.1 开始前的现场条件

自动扫频会把占空比拉到 100%，每次开始前逐项确认：

1. 车辆静止、车轮固定，风扇风道内没有工具、线束或异物；
2. 人员的手、头发、衣物和工具远离旋转部件；高转速下 2H6P 噪声约 73 dB(A)，需要佩戴听力保护；
3. PDM `0x5A0`/`0x5A1` 数据新鲜且有效；
4. 被标定的控制器在线，状态、诊断和功率帧都没有超时；
5. 不通过模拟、回放或其他开发模式发送；
6. 手动命令必须有人在场操作，离开前恢复自动模式或等租约到期。

扫频过程中上位机持续检查这些条件，任一条失效都会中止并尝试恢复自动。FanController 的中止原因包括 PDM 超时、供电离开所选档位、温度输入失联或超温、固件确认的运行停转、总线电流超过保护值、命令无应答、步骤或目标被其他 CAN 工具改写。F405 的中止原因包括离开非 Chroma 高压接通状态、最高电芯温度到 60 ℃、已确认停转、PWM/TACH 启动失败、租约到期、命令无应答。

两套标定都使用 PDM 的总线测量，同一时刻只能运行一套：一套在跑时，后端拒绝另一套的风扇命令，避免另一台风扇改变基线。

### 3.2 每个阶梯点怎么采样

开始扫频前先采集一次 0% 基线，之后每 4 个点重采一次。基线记录当时的总线电流和功率；整车背景负载会随时间漂移，只靠开始那一次基线，扣除结果会越算越偏。每条记录都带基线 ID 和对应的增量值，导出后可以逐条核对。

两种系统的采样节奏略有差别，规则相同：FanController 的稳态保持默认 6 s，前 3 s 等占空比和转速稳定，后 3 s 采样；F405 默认 5 s，前 2 s 等稳定，其余时间采样。

采样窗口内的样本先算中位数和标准差。中位数不受个别跳变样本影响；电流标准差超过 0.05 A 或功率标准差超过 2 W 时，说明负载本身还在变化，先延长一轮复采，仍不达标才中止，避免把瞬态当成稳态。

FanController 先上升后下降各扫一遍，同一个占空比有两次观测；F405 只做一次上升扫描。

FanController 扫描目标低于最低运行占空比时，会持续保持该目标；没有转速只表示还在起转死区，不会在目标与 0% 之间反复重启。上位机记录该点为 0 RPM，并以 `0x5A9` 的活动/中止状态作为固件安全结论。为兼容旧固件，上位机也不会把活动标定期间单独出现的 `0x5A3` TACH 位直接当成中止。实际输出达到最低运行占空比后，固件重新开始 3 秒停转确认；确认停转时 `0x5A9` 转为“已中止”，上位机会立即停止。供电、温度和总线电流保护不放宽。

### 3.3 命令确认

每条写入命令发出后，上位机都要等一帧“命令之后新收到的”状态帧，核对活动状态、租约、步骤和目标值：FanController 看 `0x5A9`，F405 看 `0x5AA` 和 `0x5AD`。应答只说明命令被接收，只有这种状态帧能证明控制器真的在按新目标输出，所以采样全过程持续检查，防止总线上其他 CAN 工具改写目标。1.2 s 内没有匹配的新帧就立即中止。

### 3.4 中止与收尾

中止或断开整车连接时，上位机先发送停止并核对固件状态，再关闭 PCAN；如果通信已经丢失，最终由设备端的短租约保证输出归零。上一轮后台任务退出前不能启动新一轮扫频。

重扫某一路时，该路旧推荐值立即作废。连接更换后旧记录只能导出，推荐上限同样作废。中止后扫到的记录仍可导出成 CSV/JSON；确认固件已经停止后，也可以按记录手动填入上限提交。

## 4. 整车 FanController 两档标定

### 4.1 连接与开始条件

1. 点击底部“整车 CANB”，选择真实 PCAN 通道和 500 kbit/s，通道随底栏右侧的连接设置保存。
2. 进入“整车风扇”页面，等以下状态不再是“等待数据”：
   - `0x5A2`：三路 RPM、两路实际占空比；
   - `0x5A3`：模式、目标占空比、电机与控制器温度、故障位；
   - `0x5A8`：供电状态、限功率原因、电流预算、预测总线电流；
   - `0x5AE`：是否已标定、两档上限、当前档位、Flash 错误，协议版本必须是 3。
3. 确认页面选择的供电档位与固件上报一致：
   - 低压电池：`0x5A8` 显示“低压电池”，电池档预算为 8.0 A；
   - DCDC 高压：`0x5A8` 显示“DCDC就绪”，且 PDM 实测 `Vbus - Vbat >= 300 mV`、电池支路放电 `<= 0.5 A`，并连续稳定至少 3 秒。
4. 其余门槛：无停转或 TACH 故障，电机温度低于 70 ℃，控制器温度低于 65 ℃，温度输入有效，起始总线电流不超过 8.0 A（保护值更低时取保护值）。

DCDC 档的判据由上位机用 PDM 原始测量值自行验证，不采信固件上报的“DCDC就绪”：Action 4 的人工确认会让固件报出同一个状态，只看状态无法区分自动识别和人工覆盖。固件侧接管判定只需要稳定 2 秒，上位机要求 3 秒，为测量抖动留余量。

起始电流限制 8.0 A 是给风扇留空间：三台风扇满载合计约 9.4 A，起始负载再高，扫到高占空比时必然触发保护。温度门槛同样留了余量，比中止阈值（电机 72 ℃、控制器 68 ℃）低一档，让操作者有时间反应。

### 4.2 参数与扫描点

| 参数         | 默认                 | 范围            | 说明                                     |
| ------------ | -------------------- | --------------- | ---------------------------------------- |
| 标定通道     | 回路 1               | 回路 1 / 回路 2 | 每次只扫一个回路，暂不开放双回路联合     |
| 供电档位     | DCDC                 | 低压电池 / DCDC | 决定用哪个电流预算计算推荐上限           |
| 稳态保持     | 6 s                  | 3..10 s         | 前 3 s 等稳定，其余时间采样              |
| 总线电流保护 | 电池 8 A / DCDC 18 A | 5..20 A         | 实测总线电流超过它立即中止，不等缓慢降速 |

点击“启动自动阶梯扫频”后，后台任务发送 `0x5A4` 操作码 `0x08`、Action 1 开启标定并锁定当前供电档位，然后按默认扫描点逐步下发：

`0, 5, 8, 10, 12, 15, 20, 30, 40, 50, 60, 70, 80, 90, 95, 100%`

20% 以下取点更密，用来定位起转点；先上升后下降，每个点扫两遍。每个阶梯点用 Action 2 更新目标并续租。

### 4.3 结束、导出与推荐上限

扫描结束后，上位机先发送 Action 3，等新的 `0x5A9` 确认状态为“已完成”、两路目标归零，再发送 `fan_control` 自动模式；任一环节失败都不发布推荐值，中止提示会说明记录仍可导出、可以手动填入两档上限保存。

页面表格显示每个点的 PWM、RPM、总线 V/I/P 和 ΔI/ΔP。CSV 导出汇总记录；JSON 另外导出每条记录对应的基线、基线汇总和逐样本原始数据，用于复核基线漂移。

推荐上限只取这样的点：总线总电流不超过当前档预算，且被扫回路的 RPM 大于 0。从起转点开始连续向上取，起转前沿途转速为零的低占空比点可以跳过；遇到超预算、数据无效或起转后再次失速的点就停止。没有可用点时不生成推荐值，对应输入框留空。

两路 PWM 共用同一个档位上限，所以每个供电档位都要分别扫完回路 1 和回路 2；同一个档位两次扫频都完成后，取两次中较小的值，避免轻载回路把上限抬高。只完成单个回路时，该档位不生成推荐值。

### 4.4 保存两档上限

1. 先分别扫完低压电池档和 DCDC 档，缺某一档时页面会直接提示。
2. 在 `0x5AE` 确认当前保存状态，参考推荐值填写，满足 `5% <= 电池档上限 <= DCDC 档上限 <= 100%`。
3. 点击“保存两档上限”：发送 `0x5A4` 操作码 `0x08`、Action 5，参数含确认字 `0xA5`。
4. 等 `0x5A5` 应答结果 0，再核对 `0x5AE`：bit0 为 1 表示已标定；bit1 为 0 表示最近一次 Flash 写入成功，bit1 为 1 表示写入或读回失败、可以重试；Byte1 是电池档上限，Byte2 是 DCDC 档上限。
5. “清除标定（恢复 15%）”发送 Action 6，把两档恢复为未标定的 15% 并写入 Flash。它是危险操作，只在确认不再需要旧标定时使用。

### 4.5 固件如何使用这些上限

未标定时两档都按 15% 封顶。这个占空比下风扇基本没有风量，但能保证任何供电条件都不会抽取未知的大电流；如果 15% 不足以起转，固件会锁存 TACH 故障并进入降级状态，这是该上限下的真实结果，不是故障误报。

档位选择规则：电池档、切换中、未知、数据故障和电池接管都使用电池档上限；只有 DCDC 就绪且电池未接管时使用 DCDC 档上限。

两路 PWM 共用同一套档位上限，温控、手动、关闭和失联保底都不能越过它。标定扫频可以临时用到 0..100%，但仍受电流预算限制，并且必须通过启动确认。

上限保存在主 Flash 最后两个 1KB 页里，双页轮流写入：每次提交先擦除较旧的一页，写完版本、上限、序号和 CRC 后，最后写入固定标识并读回校验；掉电中断的半条记录没有有效标识，上电不会采用。擦除一页期间 CPU 停顿 20~40 ms，可能丢个别低优先级 CAN 帧，应答帧在写入完成后才发出。

写入失败返回结果 7，`0x5AE` 置 Flash 错误位，标定状态保持“已完成”允许重试；复位后以 Flash 中最新有效记录为准。

## 5. F405 电池箱风扇标定

### 5.1 查询状态与开始条件

`0x5AA` 不是上电后一直周期发送：收到 `0x5AB` 后 F405 才开启约 5 秒的上报窗口，手动或标定租约有效时继续上报（普通窗口每 500 ms 一帧，标定中每 100 ms 一帧，结束后再报约 1 秒）。所以每次操作前先点“查询状态”。

1. F405 处于非 Chroma 的高压接通状态（页面显示“高压/DCDC 70W”），不要在充电模式下标定；
2. BMS 总状态新鲜且温度采样完整；F405 以自身的最高电芯温度做门控，达到 60 ℃ 会中止；
3. PDM `0x5A0` 新鲜，总线电流低于保护值；
4. 没有已确认停转，RPM 与占空比能正常显示；
5. 目标风扇没有 PWM/TACH 启动故障。

### 5.2 扫频与推荐上限

点“自动阶梯扫频”后，页面先查询状态，再发送 `0x5AB` 操作码 `0x03`、Action 1 采集 0% 基线，然后逐个用 Action 2 更新目标。默认扫描点：

`0, 5, 10, 15, 20, 30, 40, 50, 55, 60, 70, 80, 90, 100%`

采样、基线重采和命令确认的规则与第 3 节相同。扫完发送 Action 3，等新的 `0x5AA`/`0x5AD` 同时确认活动位清除、目标归 0% 且状态变为“已完成”；没有确认就不生成建议值。

推荐上限用增量功率分别取 35W 和 70W 预算下的最大安全占空比，并强制 `5% <= Chroma 上限 <= 高压上限 <= 100%`。取值规则与整车一致：不跨越中间的超预算点、无效点或起转后失速点；没有同时满足功率预算和转速有效的点时，推荐值留空，不要用 5% 顶替。

电池箱只有一台风扇，只有一个 PWM 通道，不需要分回路；上位机也没有独立的 Chroma 扫频通道。高压/DCDC 曲线算出建议值后，Chroma 首次接入必须用 PDM 复测该占空比的增量功率，超过 35W 就调低 Chroma 上限并重新提交。

### 5.3 提交与保存

1. 确认标定状态为“已完成”后才能提交。按钮按最后已知的完成状态保持可用，不必在 `0x5AD` 的上报窗口内抢时间；提交前可以再点“查询电池箱风扇”复核一次。
2. 填写 35W 与 70W 对应的占空比，点击“提交35W/70W上限”：命令是 `0x5AB` 操作码 `0x04`，Byte2/Byte3 是 Chroma 与高压上限，Byte4/Byte5 固定为 35 和 70，Byte6 是确认字 `0xA5`；只接受 `5 <= Chroma 上限 <= 高压上限 <= 100`。
3. 等 `0x5AC` 应答结果 0，再读 `0x5AD`：
   - bit0：RAM 当前是否使用有效标定；
   - bit1：保存等待位，清 0 才表示本次 Flash 写入完成；
   - Byte1/Byte2：Chroma 与高压上限；
   - Byte5 低 4 位：标定状态（0 未活动 / 1 活动 / 2 中止 / 3 完成）。
4. F405 在高压接通、预充或 Chroma 控制忙时不会写外部 Flash。提交后 bit1 仍是 1 时，先退出高压等后台写入；写失败会保持待重试并记录失败类型。
5. 断电前必须等 bit1 清零，然后完整重启并再次查询 `0x5AD`，确认加载值等于提交值。断电重启后仍然正确，才算保存成功。
6. 清除标定只在未上高压且未进入充电模式时执行，清除后回到未标定的 55%/55%。

## 6. 手动调试

### 6.1 租约

两套系统的手动和关闭模式都必须带有效时间，取值 1..60 秒，页面上的字段是“有效时间”或“租约”。到期后固件立即清除手动输出并回到自动温控，因此通信中断不会让风扇停在手动转速或关停状态上。FanController 用 `0x5A4` 操作码 `0x01` 发送，F405 用 `0x5AB` 操作码 `0x01` 发送。

上位机不为普通手动操作自动续租。需要保持固定转速时，操作者在到期前主动重发；自动扫频不需要人工续租，每个阶梯点的命令带 15 秒租约。

普通手动命令始终受当前供电来源的上限约束。应答结果 0 只说明命令通过了校验，实际输出可能被上限或电流预算削减；要判断实际效果，看 `0x5A2`/`0x5AA` 的实际占空比和 `0x5A8` 的限功率原因、受限目标。

### 6.2 FanController 手动调试

在“运行模式设定”卡片：

1. 目标模式选“手动调速”，填写 PWM1/PWM2（0..100%）和有效时间，建议 10 s。
2. 点击“下发模式命令”，等 `0x5A5` 应答，核对模式、目标和实际输出。
3. 观察 `0x5A2` 的三路实际 RPM 与两路实际占空比、`0x5A3` 的目标与电机/控制器最高温度和故障位、`0x5A8` 的供电状态与限功率原因、电流预算和预测电流。
4. 转速明显低于命令时，先看 `0x5A8` 是否被限功率，再看是否处于启动脉冲或斜率限制，最后才检查 TACH 故障；不要只凭转速低就判定命令失败。
5. 超温、PDM 失联、DCDC 掉线或停转时，固件会取消手动/关闭命令并恢复自动。
6. 需要临时停机时选“强制停机”，两路输入必须为 0，同样带租约。

### 6.3 F405 电池箱风扇手动调试

在“BMS 电池箱风扇”卡片：

1. 先点“查询状态”，确认模式、供电来源、实际占空比、当前上限、RPM 和保存状态。
2. 目标模式选“手动调速”，填写占空比和租约，点击“下发控制”，等 `0x5AC` 应答。
3. 观察 `0x5AA` 的实际占空比与当前供电来源的上限。
4. 低压待机也可以手动测试，但低压来源固定按未标定的 55% 封顶。
5. Chroma 充电或整车高压运行中，最高温度达到 70 ℃ 后固件会取消已有的手动/关闭命令并拒绝新的手动/关闭命令，不要尝试绕过。
6. 测试结束选“自动温控”，或等租约到期；确认页面回到自动后停止继续查询和控制。

## 7. 现场验收记录

每次上车标定或修改参数后，按以下顺序留记录：

1. 连接角色，以及 `0x5A2..0x5A9`/`0x5AE` 或 `0x5AA..0x5AD` 的状态；
2. 标定 CSV/JSON，字段包含通道、供电档位、方向、PWM、RPM、总线 V/I/P、基线 ID、基线与增量数据、时间戳；
3. 提交前的两档上限、提交后的应答结果和状态帧；
4. 断电重启后的复核：FanController 看 `0x5AE`，F405 查询 `0x5AD`；
5. 现场环境：供电来源、温度、车辆状态和异常事件，便于下次复现；
6. 中止原因（PDM 超时、供电变化、温度、停转、电流、租约、用户停止）必须记录下来，弄不清原因就不要直接重试。

## 8. 已知不足

- FanController 的功率预测电流表仍是 30/50/70/100% 的临时值。标定得到的上限只用于封顶，不会更新这张表，用台架实测值替换它仍是待办事项。
- Chroma 35W 上限由高压/DCDC 曲线推导，没有独立的充电侧自动扫频，需要人工用 PDM 复测。
- 双回路联合扫频未开放，每个供电档位都要分别扫两个回路，各跑一遍完整流程。
