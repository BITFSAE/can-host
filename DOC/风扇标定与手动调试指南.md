# 风扇标定与手动调试指南

> 适用仓库：`can-host`、`FanController`、`BMS_MASTER_F405`、`PDM`。
> 接口权威：整车风扇以 `FanController/Doc/风扇控制.md` 和 `Core/Src/fan_controller.c` 为准；电池箱风扇以 `BMS_MASTER_F405/DOC/风扇控制.md`、`App/bms_fan.c` 和 `DOC/CAN通信协议.md` 第 8 节为准；PDM 以 `PDM/Doc/CAN接口.md` 为准。
> 本文只描述当前已经实现的行为。所有写命令只允许通过真实 PCAN 和整车 CANB 发送，模拟连接、BMS 只读 CANB 和 Mac 开发模拟都不能下发标定或手动命令。
> 最后复核：2026-09-03，按当前两仓库固件与 can-host 风扇页面核对。

## 1. 两套散热风扇系统

车队有两套独立风扇系统，接线、控制器和 CAN 接口完全不同。两者都叫“风扇”，但不要把对方的帧当成另一台的接口。

| 系统 | 控制器 | 驱动的风扇 | 命令与状态 | 标定内容 | 保存位置 |
|---|---|---|---|---|---|
| 整车水箱/控制器散热 | FanController（STM32F103C8T6） | PWM1：2×4114N/2H4PU；PWM2：1×4114N/2H6P | CANB：命令 `0x5A4`，应答 `0x5A5`，状态/诊断/功率/标定 `0x5A2..0x5A9`，上限 `0x5AE` | 低压电池档与 DCDC 档各自的最大 PWM 上限（%） | FanController 内部主 Flash 最后两个 1KB 页（`0x0800F800` / `0x0800FC00`） |
| 电池箱内部风扇 | BMS_MASTER_F405 主控（STM32F405RGT6） | 1× 电池箱风扇（当前资料为 ebm-papst 3214 J/2H4P） | CANB：命令 `0x5AB`，应答 `0x5AC`，状态 `0x5AA`，标定/上限 `0x5AD`；CAN1 另有监视帧 `0x186250F4` / `0x186E50F4` | Chroma 充电 35W 上限与整车高压/DCDC 70W 上限（%） | F405 外部 Flash Sector8 的独立 RecLog（magic `0x464E`、版本 1、3 字节记录） |

### 1.1 需要注意的连接角色

- `CAN1`（BMS 主监视）和 `BMS CANB`（只读镜像）用于 BMS 监视，不能发送风扇写命令。
- 风扇写命令统一走 **整车 CANB**。即使电池箱风扇由 F405 主控驱动，也必须通过“整车 CANB”连接发送 `0x5AB`；它和 `BMS CANB` 是两种服务，不要混用。
- 整车 CANB 位率默认 500 kbit/s。250 kbit/s 只属于旧充电机/过渡场景，不要在风扇标定时选择它。
- 模拟连接只用于界面开发，所有标定、手动和提交按钮都会由后端再次拦截。

### 1.2 PDM 输入与电流符号

PDM 每 100 ms 发送两帧：

| CAN ID | 内容 | 用途 |
|---|---|---|
| `0x5A0` | OR-RING 后低压总线电压/电流/功率/电量 | 整车低压总负载，标定和功率保护的主依据 |
| `0x5A1` | 低压电池支路电压/电流/功率/电量 | DCDC 是否接管、电池是否仍在放电，以及电池档预算判断 |

电流方向已实测确认：**正电流 = 放电/负载消耗，负电流 = 充电**。四字段同时为无效哨兵值时才表示该路 INA226 离线，单字段越界时优先由固件按有效值判断。

## 2. 为什么要标定、实际标什么

当前控制策略**不是**把转速曲线写入固件。标定解决的是“供电能力允许风扇转多快”的问题：

- FanController：温控算法只计算理论占空比，固件再按“电池档/DCDC 档上限 → 功率预算仲裁 → 启动/升降斜率”执行。当前固件中的“功率预测电流表”仍是 30/50/70/100% 占位值，所以不同供电条件下的可安全 PWM 必须由车上的 PDM 实测得到；标定得到的上限会用于封顶，但不会自动更新固件里的功率预测表。
- F405 电池箱风扇：自动温控和普通手动命令都会按当前供电来源的 PWM 上限封顶。未标定时，电池箱风扇按 55% 封顶；只有高压/DCDC 标定会话可以临时越过该上限扫频，但仍受固件安全看门狗和绝对电流保护约束。

标定测量的是：

- PWM 占空比与低压总线电流/功率的稳态关系；
- 扣除邻近 0% 基线后的增量电流/增量功率；
- 三路 RPM 是否真正起转，用于识别停转、卡滞或 TACH 故障；
- FanController 标定还要区分低压电池与 DCDC 两种供电档位；
- F405 电池箱风扇标定只做一次高压/DCDC 扫频，用同一曲线推导 35W 与 70W 上限，并额外要求 Chroma 充电时复测，不能直接把 DCDC 曲线当成充电曲线。

标定完成后的“推荐值”只是上位机建议，写入固件才是真正生效。写入失败时以命令应答和状态帧为准，界面显示成功不等于已经保存到 Flash。

## 3. 开始标定前的通用安全条件

每次开始自动扫频前，现场必须确认：

1. 车辆静止、车轮已固定，风扇风道没有工具、线束或异物遮挡；
2. 人员手、头发、衣物和工具远离旋转部件；高转速时 2H6P 噪声约 73 dB(A)，应佩戴听力保护；
3. PDM `0x5A0`/`0x5A1` 新鲜且有效；
4. 对应控制器在线，状态、诊断和功率帧年龄不超过页面要求；
5. 不允许模拟、回放或其他开发模式下发送；
6. 一切手动命令只在必要时使用，不得无人值守；离开前必须恢复自动模式或等租约到期。

自动扫频期间，任一安全条件失效都会中止并尝试恢复自动：

- FanController：PDM 超时、供电离开所选档位、温度输入失联/超温、停转、总线电流超过保护值、命令无应答、用户点击停止；
- F405 电池箱风扇：离开非 Chroma 高压接通状态、最高电芯温度达到 60℃、已确认停转、PWM/TACH 启动失败、租约到期、命令无应答、用户点击停止。

## 4. 整车 FanController 两档功率标定

### 4.1 连接与检查

1. 点击底部 **整车 CANB**，选择真实 PCAN 通道和 500 kbit/s（通道保存在底栏右侧连接设置）。
2. 进入 **整车风扇** 页面，等待以下状态不是“等待数据”：
   - `0x5A2`：三路 RPM、两路实际占空比（100 ms）；
   - `0x5A3`：模式、目标占空比、电机/控制器温度和故障位（500 ms）；
   - `0x5A8`：供电状态、限功率原因、电流预算、预测总线电流（100 ms）；
   - `0x5AE`：当前是否已标定、两档上限、当前档位和 Flash 错误（500 ms）。
3. 确认供电档位与页面选择一致：
   - **低压电池**：`0x5A8` 供电状态为“低压电池”，电池档预算通常为 8.0A；
   - **DCDC 高压**：固件状态为“DCDC就绪”，且 PDM 实测 `Vbus - Vbat >= 300mV`、电池支路放电 `<= 0.5A` 并连续稳定至少 3 秒。
4. 开始前还要满足：无停转/TACH 故障、电机温度低于 70℃、控制器温度低于 65℃、温度输入有效、起始 PDM 总线电流不超过 8.0A。

### 4.2 自动阶梯扫频

标定面板参数：

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 标定通道 | 回路 1 | 回路 1 / 回路 2 | 先单回路标定，暂不开放双回路联合 |
| 供电档位 | DCDC | 低压电池 / DCDC | 决定推荐上限的预算 |
| 稳态保持 | 6 s | 3..10 s | 前 3 s 稳速、后 3 s 采集 |
| 总线电流保护 | 电池 8A / DCDC 18A | 5..20A | 超过立即中止，不等待慢速降速 |

点击 **启动自动阶梯扫频**，后台会话执行：

1. 后端前置检查；DCDC 档会额外连续验证 3 秒实测判据，不接受固件单方面上报的“DCDC就绪”。
2. 发送 `0x5A4` 操作码 `0x08`、Action 1 开启标定会话并锁定当前供电档位。
3. 两路 0% 采集基线；每个阶梯用 Action 2 更新目标并续租，默认扫描点：
   `0, 5, 8, 10, 12, 15, 20, 30, 40, 50, 60, 70, 80, 90, 95, 100%`。
4. 先上升后下降双向扫描；每 4 个点重新采集一次 0% 基线，记录逐样本原始数据，便于复核基线漂移。
5. 每点用中位数统计，电流标准差 >0.05A 或功率标准差 >2W 时延长采集；仍不稳定则中止。
6. 结束后先发送 Action 3 停止标定，再发送 `fan_control` 自动模式；任一失败都会显示恢复失败原因。

标定完成后：

- 页面表格显示每点的 PWM、RPM、总线 V/I/P、ΔI/ΔP；
- CSV 导出汇总记录，JSON 导出包含每条记录对应的基线、基线和逐样本原始数据；
- 推荐上限只计算“总线总电流不超过该档预算且被扫回路有有效 RPM”的最大占空比；没有可用点时不生成假建议；
- 同一档位重复扫不同回路时保留更保守的值。

### 4.3 保存两档上限

1. 先分别扫完低压电池档和 DCDC 档。若缺少某一档，页面会明确提示。
2. 在 `0x5AE` 确认当前保存状态；参考推荐值填写：
   `5% <= 电池档上限 <= DCDC档上限 <= 100%`。
3. 点击 **保存两档上限**：后端发送 `0x5A4` 操作码 `0x08`、Action 5，参数 `0xA5` 确认字。
4. 等待 `0x5A5` 应答结果 0；再核对 `0x5AE`：
   - bit0 = 1：已标定；
   - bit1 = 0：最近一次 Flash 写入成功；bit1 = 1：最后写入或读回失败，可重试；
   - Byte1/Byte2：当前 RAM/Flash 两档上限。
5. 点击 **清除标定** 会发送 Action 6，把两档恢复为未标定 15% 并写 Flash；清除按钮是危险操作，只在确认需要时使用。

### 4.4 固件如何消费

- 未标定时两档都按 **15%** 封顶；该值保证不会突然抽取未知大电流，但也可能不足以起转，此时固件会报 TACH/DEGRADED，属于“上限下确实无法工作”的真实状态。
- 标定值按当前供电档位选择：电池档、切换中、未知、数据故障、电池接管都使用电池档；只有 DCDC 就绪且电池未接管时使用 DCDC 档。
- 两路 PWM 共用同一套按供电档位的上限；温控、手动、关闭和失联保底都不能越过它。标定扫描会话可以临时越过保存上限到 0..100%，但仍受电流预算仲裁和启动确认。
- Flash 使用两个 1KB 页轮流写入，记录包含版本、序号、CRC、magic；每次提交先擦除较旧页再写，最后写 magic 提交标志并读回校验。掉电中断的半条记录没有有效 magic，上电不会采用。
- 写失败返回结果 7，`0x5AE` 置 Flash 错误位，会话保持“已完成”允许重试；复位后以 Flash 中最新有效记录为准。

## 5. F405 电池箱风扇功率标定

### 5.1 状态查询与条件检查

F405 的 `0x5AA` 不是上电后永久周期发送。收到 `0x5AB` 后才开启约 5 s 窗口；手动或标定租约有效时继续上报。所以要先点击 **查询状态**：

1. F405 必须处于 **非 Chroma 的高压接通状态**（页面显示“高压/DCDC 70W”），不要处于充电模式；
2. BMS 总状态新鲜，最高电芯温度低于 60℃；
3. PDM `0x5A0` 新鲜，总线电流低于保护值；
4. 没有已确认停转，RPM 与占空比能正常显示；
5. 目标风扇没有 PWM/TACH 启动故障。

### 5.2 自动阶梯扫频

页面“高压/DCDC 标定会话”中的 **自动阶梯扫频** 会先查询状态，再执行：

1. 发送 `0x5AB` 操作码 `0x03`、Action 1，采集 0% PDM 基线；
2. 依次发送 Action 2 更新，默认扫描点：
   `0, 5, 10, 15, 20, 30, 40, 50, 55, 60, 70, 80, 90, 100%`；
3. 每 4 个点重新采集邻近 0% 基线；
4. 每点用稳态 PDM 中位数计算增量功率，电流标准差 >0.05A 或功率标准差 >2W 时中止；
5. 结束后发送 Action 3 停止，风扇立即归 0%，状态变为“已完成”；
6. 用增量功率分别选择：
   - 35W 预算对应的最大安全占空比（Chroma 上限）；
   - 70W 预算对应的最大安全占空比（高压/DCDC 上限）；
   - 强制 `5% <= Chroma <= 高压 <= 100%`。

电池箱风扇只有一台，不需要分 PWM1/PWM2；也**没有**独立的 Chroma 扫频通道。高压/DCDC 曲线算出建议值后，Chroma 首次接入必须用 PDM 复测该占空比的增量功率，不能只照搬 DCDC 结果。

### 5.3 提交与保存

1. 确认标定会话为“已完成”（停止后才允许提交）。
2. 填写 35W 与 70W 对应占空比，点击 **提交35W/70W上限**：
   - 命令为 `0x5AB` 操作码 `0x04`；
   - Byte4 固定 35，Byte5 固定 70，Byte6 固定确认字 `0xA5`；
   - 只接受 `5 <= Chroma上限 <= 高压上限 <= 100`。
3. 等待 `0x5AC` 应答结果 0；再读取 `0x5AD`：
   - bit0：RAM 当前是否使用有效标定；
   - bit1：保存等待/重试标志，**清 0 才表示本次 Flash 写入完成**；
   - Byte1/Byte2：Chroma 与高压上限；
   - Byte5 低 4 位：当前标定会话状态（0 未活动 / 1 活动 / 2 中止 / 3 完成）。
4. F405 在高压接通、预充或 Chroma 控制忙时不会执行外部 Flash 写入。提交后若 bit1 仍为 1，先退出高压并等待后台写入；写入失败会保持待重试并记录失败类型。
5. 断电前必须等 bit1 清零；之后完整重启，再次查询 `0x5AD`，确认加载值等于提交值。保存成功的唯一最终证据是断电重启后仍然正确。

清除标定只允许在未上高压且未进入充电模式时执行；操作后回到未标定 55%/55%。

## 6. 手动调试风扇转速

### 6.1 租约保护机制

两套系统的手动/关闭模式都必须携带 1..60 s 租约：

- FanController：通过 `0x5A4` 操作码 `0x01` 发送；
- F405：通过 `0x5AB` 操作码 `0x01` 发送；
- 租约到期后固件立即清除手动/关闭输出并回到自动温控；
- **上位机不会为用户手动操作自动续租**。需要保持固定转速时，操作者在租约到期前主动重发；自动标定会话会在每步操作中携带短租约续租。

普通手动命令始终受当前供电来源上限约束。不要以为“命令成功且 ACK=0”就等同于“实际输出等于输入”；请同时看 `0x5A2`/`0x5AA` 的实际占空比和 `0x5A8` 的限功率原因/受限目标。

### 6.2 FanController 手动调试

在 **运行模式设定** 卡片：

1. 目标模式选 `1 手动调速`；输入 PWM1/PWM2（0..100%）；有效时间建议 10 s。
2. 点击 **下发模式命令**，等待 `0x5A5` 应答和模式、目标、实际输出。
3. 观察：
   - `0x5A2` 三路实际 RPM 与两路实际占空比；
   - `0x5A3` 当前目标、电机/控制器最高温度和故障位；
   - `0x5A8` 供电状态、限功率原因、电流预算和预测电流。
4. 如转速明显低于命令，先看 `0x5A8` 是否被限功率，再看是否处于启动脉冲/斜率限制，最后检查 TACH 故障；不要仅凭 RPM 低就判定命令失败。
5. 手动或关闭命令在超温、PDM 失联、DCDC 掉线或停转时会被固件安全逻辑取消并恢复自动。

如需临时停机，选择 `2 强制停机`，两路输入必须为 0；同样带租约。

### 6.3 F405 电池箱风扇手动调试

在 **BMS 电池箱风扇** 卡片：

1. 先点击 **查询状态**，确认模式、供电来源、实际占空比、当前上限、RPM 和保存状态。
2. 目标模式选 `1 手动调速`，输入占空比和租约；点击 **下发控制**，等待 `0x5AC` 应答。
3. 观察 `0x5AA` 实际占空比与当前来源上限。低压待机也可显式手动测试，但低压来源固定按未标定 55% 封顶。
4. Chroma 充电或整车高压运行中，最高温度达到 70℃ 后，固件会取消已有手动/关闭覆盖并拒绝新的手动/关闭命令；不要尝试绕过。
5. 测试结束选择 `0 自动温控`，或等租约到期；确认页面回到自动，并停止继续查询/控制。

## 7. 保存原理与现场复核

### 7.1 FanController 内部 Flash

- 保存值：`[已标定位, 电池档上限%, DCDC档上限%]` 的 12 字节双页记录；
- 地址：主 Flash 最后两个 1KB 页 `0x0800F800` / `0x0800FC00`，程序区已缩到 62KB；
- 写入策略：RAM 先生效，随后擦除较旧页、写入新记录、写 magic 提交标志并读回校验；
- 掉电中断或校验失败：不会采用半条记录；上电回退未标定 15%；
- 写/读回失败：命令结果 7，`0x5AE` bit1 置位；成功后 bit1 清零，重新上电后再次核对 `0x5AE`。

### 7.2 F405 外部 Flash

- 保存值：`[0未标定/1已标定, Chroma上限%, 高压上限%]`，3 字节 payload；
- 位置：外部 SPI Flash Sector8，独立 RecLog，magic `0x464E`、版本 1、CRC-16；
- 无效记录：记录缺失、CRC 错误或范围不符合 `5 <= Chroma <= 高压 <= 100` 时回退 55%/55%；
- 写请求：提交/清除先更新 RAM 并置 `0x5AD` bit1 保存等待；退出高压、预充或 Chroma 控制忙后，后台写入并校验；
- 写入失败：bit1 保持 1，并进入 2 秒退避，失败记录类型可在 F405 CLI `flash show` 查看；
- 现场验收：bit1 清零 → 完整断电重启 → 查询 `0x5AD` → 与提交值一致。

## 8. 当前界面能力与后续完善点

### 8.1 已实现能力

- FanController：实时遥测、供电/功率仲裁、三路 TACH、故障诊断、策略查询/写入、手动/关闭租约、自动阶梯扫频、进度条、CSV/JSON 导出、两档上限保存/清除、`0x5AE` 和 Flash 错误显示；
- F405：限时查询、手动/关闭租约、高压/DCDC 自动阶梯扫频、35W/70W 建议值、手动标定步骤、提交/清除、保存等待位和最终保存状态；
- 所有写命令按操作码和序号匹配 `0x5A5` / `0x5AC` 应答；无应答时明确提示，不静默当作成功。

### 8.2 已知不足与建议

以下内容目前**尚未实现**，不要按已有功能描述：

1. 标定曲线没有 Canvas 图表，只有表格、进度条和导出数据；现场只能看 CSV/JSON 后处理。
2. 没有“导入历史标定/预设”功能；FanController 有 JSON 导出，但没有反向导入和写回。
3. F405 自动扫频只有 CSV 导出，没有 JSON 导出。
4. PPR（每转脉冲数）没有 CAN 配置项；两套固件都固定按每圈 2 个脉冲计算，更换风扇后仍需改固件。
5. FanController 的功率预测占位表（`lookup_pwm1_current` / `lookup_pwm2_current`）仍按 30/50/70/100% 的占位值，本次标定结果不会更新该表；它只是把可安全输出上限写入 Flash。真正用于“功率预测”的电流表仍需台架逐点标定后固化。
6. F405 的 Chroma 35W 上限只是从高压/DCDC 曲线推导并额外要求复测；尚未实现独立的充电侧自动扫频。
7. 手动操作没有自动心跳续租，长时间无人值守保持固定转速是危险的；建议后续增加“仅标定会话自动续租”并继续禁止普通手动自动续发。

## 9. 现场验收清单

每次上车标定或修改后，按以下顺序留记录：

1. 截图或记录页面连接角色、`0x5A2..0x5A9/0x5AE` 或 `0x5AA..0x5AD` 状态；
2. 保存标定 CSV/JSON，字段包含通道、供电档位、方向、PWM、RPM、总线 V/I/P、基线 ID、基线与增量数据、时间戳；
3. 记录提交前的两档上限、提交后 ACK 结果和状态帧；
4. FanController 断电重启后核对 `0x5AE`；F405 断电重启后查询 `0x5AD`；
5. 记录实际台架/赛道环境（供电来源、温度、车辆静止条件、异常事件），便于下次拟合和复现；
6. 任何自动中止都必须记录原因（PDM 超时、供电变化、温度、停转、电流、租约、用户停止），不要静默重试。
