# 开发与发布

本文负责上位机的安装、源码运行、测试、打包、CI、发布和软件更新。页面与车辆连接操作见 [`CAN上位机与工具使用.md`](CAN上位机与工具使用.md)。

## 1. 环境与安装

| 环境                    | 要求                                                                                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| Windows 10/11           | PEAK PCAN 驱动、PCAN-Basic、Microsoft Edge WebView2 Runtime                                                    |
| Apple Silicon macOS 12+ | 系统 WKWebView；实体 PCAN 需 MacCAN `libPCBUSB` 0.13+ 且包含 arm64                                             |
| 源码运行                | Python 3.11+、`requirements.txt`；串口遥测由其中的 pyserial 提供（两个发布包也随包携带，供“遥测数据模拟”使用） |

### Windows 发布版

从 [GitHub Releases](https://github.com/BITFSAE/can-host/releases) 或 [CNB 镜像](https://cnb.cool/totok22/can-host/-/releases) 下载：

- `BITFSAE_CAN_Host_vX.Y.Z_setup.exe`：每用户安装到 `%LOCALAPPDATA%\Programs\BITFSAE_CAN_Host`，可创建快捷方式并从系统卸载。
- `BITFSAE_CAN_Host_vX.Y.Z.zip`：便携版；必须保留完整 `BITFSAE_CAN_Host` 目录，不能只复制 exe。

### macOS 发布版

下载 `BITFSAE_CAN_Host_macOS_arm64_vX.Y.Z.dmg`，将应用拖入“应用程序”。当前包为 ad-hoc 签名，首次启动如被阻止，在“系统设置 → 隐私与安全性”中确认打开。

实体 PCAN-USB 依赖第三方 MacCAN `libPCBUSB`，通常安装到 `/usr/local/lib`。先用 MacCAN Monitor 验证适配器，再连接上位机。串口设备由 pyserial 枚举为 `/dev/cu.*`。当前包不支持 Intel Mac，也未做 Apple 公证。

## 2. 源码运行与测试

Windows：

```powershell
py -3.11 -m venv .venv-canhost
.\.venv-canhost\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m canhost
```

macOS：

```bash
python3 -m venv .venv-canhost
.venv-canhost/bin/python -m pip install -r requirements.txt
.venv-canhost/bin/python -m canhost
```

运行全部单元测试：

```bash
python -m unittest discover -s Tests -p "test_*.py" -v
```

前端调试可加 `--debug`。本地源码运行会显示“调试模拟”，Windows 与 macOS 冻结发布包均隐藏该入口并由后端拒绝模拟连接。模拟数据和模拟命令只用于界面与协议回归；对实体设备操作和发布验收仍要求真实 PCAN。

### 浏览器预览界面

没有 PCAN 硬件时用下面的命令审阅排版（间距、换行、过期配色、控件宽度）：

```bash
.venv-canhost/bin/python scripts/ui_preview.py
```

脚本用包内固定的模拟数据生成一份完整页面数据，把 `canhost/web` 复制到临时目录并在 `core.js` 之前注入 `window.pywebview` 替身，然后在 `http://127.0.0.1:8812/index.html` 提供页面（端口被占用时用 `--port` 换一个）。`?mock=` 切换状态：`live` 已连接实体 CANB 的赛场状态、`stale` 数据超出新鲜窗口、`calib` 整车标定进行中、`sim` 内置模拟通道（只能读、不能下发）。数据是模拟值，但页面脚本原样运行，可以直接测量元素几何；脚本抛出的错误与未处理的 Promise 拒绝收集在 `window.__previewErrors`。

## 3. 本地打包

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File build_windows.ps1
```

脚本运行测试、PyInstaller 和冻结包自检（`dist\BITFSAE_CAN_Host\BITFSAE_CAN_Host.exe --packaging-smoke-test`），生成：

| 产物                                         | 用途                 |
| -------------------------------------------- | -------------------- |
| `release/BITFSAE_CAN_Host_v<版本>.zip`       | 便携版和软件内更新包 |
| 同名 `.zip.sha256`                           | 更新器校验           |
| `release/BITFSAE_CAN_Host_v<版本>_setup.exe` | Inno Setup 安装器    |

本机缺少 Inno Setup 6 时只生成 ZIP；CI 使用 `-RequireInstaller`，缺少安装器即失败。`-Label <标签>` 可覆盖产物标签。

两个平台的冻结包自检内容一致：验证随包的 Protobuf、MQTT、pyserial、本地遥测帧生成器和 PCAN Python 后端真的可用，核对随包更新说明与 `canhost/web` 存在，并确认两个发布包都不开放“调试模拟”标志且后端拒绝该连接模式。

### Apple Silicon macOS

```bash
bash build_macos.sh
```

脚本要求 arm64 Python 3.11，运行测试、PyInstaller、自检、最低系统版本核对和 ad-hoc 签名，生成首次安装/手动覆盖使用的 DMG、软件内更新使用的 `-update.zip`，以及两者的 SHA-256 文件。更新 ZIP 由 `ditto --sequesterRsrc --keepParent` 从签名后的 `.app` 生成，保留应用包元数据。自检同时加载 Protobuf、MQTT、pyserial、本地遥测帧生成器和 PCAN Python 后端。可传入标签；非默认 Python 用 `CANHOST_PYTHON=/path/to/python3.11` 指定。

构建机装有 `libPCBUSB` 时会验证冻结程序能加载驱动；这项检查不打开适配器，也不代替实体收发测试。

## 4. CI 与发布

| 配置                               | 触发                      | 结果                                                         |
| ---------------------------------- | ------------------------- | ------------------------------------------------------------ |
| `.github/workflows/tests.yml`      | main push、Pull Request   | Windows 上运行单元测试                                       |
| `.github/workflows/release.yml`    | `v*` 标签、手动触发       | 并行生成 Windows 与 macOS 产物；标签构建发布到 GitHub 和 CNB |
| `.github/workflows/cnb-mirror.yml` | push、手动触发            | 同步分支、标签；手动补做发布镜像                             |
| `.cnb.yml`                         | CNB push、定时或 API 触发 | Linux 测试；定时补齐 GitHub 正式发布                         |

发布步骤：

1. 在 [`CHANGELOG.md`](../CHANGELOG.md) 增加 `## vX.Y.Z — YYYY-MM-DD` 小节，用条目写清面向使用者的变化；同时把 `canhost/__init__.py` 的 `__version__` 改成同一版本号。
2. 提交并推送代码，确认主分支测试通过。
3. 创建并推送 `vX.Y.Z` 标签；预发布使用 `vX.Y.Z-rcN`。
4. 确认 GitHub 与 CNB 均包含 7 个附件：Windows ZIP、ZIP 校验、安装器，以及 macOS DMG、DMG 校验、更新 ZIP、更新 ZIP 校验。

标签主体必须与 `__version__` 一致。发布流程需要 GitHub `contents:write` 和仓库 Secret `CNB_TOKEN`；访问凭据不得写入仓库或日志。

### 版本说明的来源

Release 正文、软件内更新弹窗的“版本说明”和升级后“更新完成”弹窗共用同一份条目，全部由 `CHANGELOG.md` 的对应小节生成：

| 文件                       | 作用                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `scripts/set_version.py`   | 打包前写入 `canhost/release_info.py`（当前版本、日期、条目和版本历史），随程序一起发布，离线可用 |
| `scripts/release_notes.py` | 生成 GitHub Release 正文和条目 JSON，并给出安装包与依赖说明                                      |

两个平台的构建脚本（`build_windows.ps1`、`build_macos.sh`）在打包前自动调用它们，因此不需要手工维护说明。非 `vX.Y.Z` 的构建标签（手动触发的短 SHA）会跳过写入，避免把构建号当成版本号。`canhost/release_info.py` 由脚本生成、不入库；发布链路之外改从仓库 `CHANGELOG.md` 读取。

## 5. 软件更新

Windows 与安装位置可写的 macOS 发布版启动后并行检查 CNB 镜像与 GitHub 的正式版本，按语义版本号选择较新结果；两端版本相同时使用 CNB 的下载地址。这样既保留国内下载路径，也避免 GitHub Release 已发布而 CNB 尚在同步时误报“已是最新”。任一更新源失败时仍使用另一端的有效结果，只有两端都没有有效结果才判定检查失败。发现新版本后，侧栏版本信息旁显示下载图标；用户点击“下载 vX.Y.Z”后，程序选择当前平台的更新 ZIP。连接下载源、获取 SHA-256、校验和解压使用阶段状态，实际收到更新包字节且总大小已知后才显示百分比、已下载大小和速度，不用 0% 代替尚不可量化的准备过程。下载与 SHA-256 校验完成后按钮变为“重启更新”，用户再次点击，程序自动退出、替换安装目录并启动新版。

两个平台的安装助手都在安装目录之外运行，并要求新版在 45 秒内回报匹配的进程号和版本号；启动失败、健康信号超时或版本不符时自动恢复旧目录并重新打开旧版。Windows 助手额外保留 Inno Setup 卸载文件，并对短暂占用的安装目录有限重试；macOS 助手交换整个 `BITFSAE CAN Host.app`，因此更新 ZIP 必须来自签名完成后的应用包。若 macOS 应用所在位置不可写（例如直接从只读 DMG 运行），更新窗口改为“下载 DMG”，由用户覆盖安装，不尝试提权或绕过系统权限。

更新检查和下载每次都重新读取 Windows 当前系统代理，不沿用进程启动时缓存的代理配置。若代理端口拒绝连接（`WinError 10061`），公开更新地址会自动直连重试一次；直连仍失败时，错误会明确提示关闭失效的 Windows 系统代理或重新启动代理软件，不需要重启电脑。

更新弹窗的“版本说明”逐条显示本次变化（不再整段贴 Release 正文），底部可展开正文原文和历史版本列表。升级后的首次启动显示“更新完成”弹窗：更新前后版本号、发布日期、本次更新内容，以及“打开发布页”和“查看历史版本”入口。说明优先取检查更新时缓存的 Release 条目，其次取随包说明，最后取仓库 `CHANGELOG.md`；三条都为空的旧版本才提示到发布页查看。判定“这次启动是否发生过升级”用的是上次成功启动写入的版本标记（`installed-version.json`），安装包覆盖安装和软件内更新都会命中，界面把标记写回后才算升级完成。

历史版本列表只带版本号、日期和条目，不带 Release 正文：这份列表每秒随更新状态轮询重新发到界面，带正文会让每次发出的数据大三倍，而界面只读条目。要看某个版本的完整表述时用当前版本的正文原文或打开发布页。

v0.9.1 和 v0.9.2 内置的旧助手会继承安装目录，下载新包不能改变已经运行的旧助手。由这两个版本升级时需手动运行一次 v0.9.3 Setup 覆盖安装；从 v0.9.3 开始，后续软件内更新使用修复后的助手。

Windows 更新日志位于 `%LOCALAPPDATA%\BITFSAE\CAN Host\update-logs`，macOS 位于 `~/.local/state/can-host/update-logs`，最多保留 20 份。旧版本备份位于安装目录同级，超过 15 分钟回退窗口后由后续启动清理。

源码运行只检查版本，不能下载安装包或替换安装目录。macOS 正常安装后采用“下载更新 → 重启更新”两步流程；只有安装位置不可写时才回退为系统浏览器下载 DMG 后手动覆盖。

## 6. 常见失败

| 现象                                     | 检查                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| Windows 未生成安装器                     | 安装 Inno Setup 6；CI 必须使用 `-RequireInstaller`                                         |
| macOS 无法加载 PCBUSB                    | 检查 `libPCBUSB` 版本、arm64 架构和 `/usr/local/lib`；先用 MacCAN Monitor 验证             |
| 标签构建拒绝发布                         | 核对标签主体与 `canhost.__version__`                                                       |
| GitHub 已发布但 CNB 失败                 | 检查 `CNB_TOKEN` 权限；用 `cnb-mirror.yml` 手动补做                                        |
| Windows 更新后回滚                       | 查看固定日志目录中的最新日志，定位退出、目录持续占用、替换或健康确认失败                   |
| Windows 更新检查报 `WinError 10061`      | 系统代理指向未运行的本地代理端口；新版会自动直连重试，旧版可关闭 Windows 系统代理或重启代理软件 |
| macOS 更新检查或 MQTT TLS 报证书校验失败 | 旧包缺少随包 CA 证书；升级到包含 certifi 的发布包；若新版仍复现，检查系统时间和代理/防火墙 |
