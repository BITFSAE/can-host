# BITFSAE BMS Control Desk

这是 F405 BMS 主控的 Windows CAN 上位机。程序默认连接 PCAN-USB 的 CAN1，也支持 CANB 500 kbit/s、Legacy CANB 250 kbit/s，以及不接硬件的内置模拟数据。

## 已实现功能

- 运行总览：集中显示状态机、统一故障码及解析、包电压/电流、PRE电压、单体压差、SOC、三路继电器、HV_ACC、实体充电信号、安全回路、预充耗时、六个模组平均值、温度、风扇、IMD、电压/电流曲线、充电计时和预计充满时间。当前不显示SOP。
- 电芯与温度：按六个从控的物理顺序，在同一页面同时显示138串电压和48路温度；顶部显示当前四项阈值和全包极值，每个模组显示电压范围、压差和温度范围。正常数据不反复标注完整性，只有通信中断或数据缺失时才显示醒目提示。
- 故障与记录：只读显示32项告警、统一故障码、19个保护开关当前回报、故障码变化和Flash重要故障日志。每项告警直接显示当前阈值、固定判定条件和确认时间，不在主界面重复显示bit编号。
- 参数与命令：所有写入集中在一个独立页面，包括四项阈值、19个开关、充电请求、电流方向、充电机类型、RTC校时、日志清除和故障复位。写命令必须收到请求计数和命令码一致的主控应答。
- CAN 监视器：查看最近 320 帧，按方向或文本筛选；默认记录为单文件 `.bmslog`，也可导出兼容表格工具的 CSV。两种文件都能重新打开，并按 0.25..10 倍速度播放、暂停和拖动时间位置，全部状态页面随历史帧恢复。
- 故障历史：把 `fault_code` 每次增加和清除的位解析为中文故障项，记录变化前后故障码和时间；实时会话与历史回放使用同一套显示。
- 工程导入导出：`.bmsproj`保存总线用途和PCAN通道、阈值、19个告警开关、充电请求、电流方向、充电机类型、工程说明和页面偏好。导入只填充界面，不会自动连接或写主控。
- CANB：解析统一故障帧、告警等级、SOP、IVT-S结果、Legacy充电反馈及放电总状态。CANB没有从控单体原始帧，因此不能显示完整138串和48路温度；SOP和IVT原始数据保留在CAN监视器、记录和后台解析中，当前总览不单独设置面板。
- 界面：监视与写入操作分区；侧栏选中项只改变文字和图标颜色，不使用装饰竖条或背景框。绿色表示正常，黄色表示二级告警，红色表示一级故障、无效数据或危险操作，青色只用于交互和低限定位。左下角显示BITFSAE、软件版本、版本日期和目标主控。`Alt+1..4`切换四个监视页，`Alt+5`进入参数与命令页。默认缩放为110%；`Ctrl++`放大、`Ctrl+-`缩小、`Ctrl+0`恢复默认110%，也支持`Ctrl+鼠标滚轮`。缩放范围为80%..130%，关闭后会记住当前比例；程序会同步修正可视高度，底部状态栏和页面滚动区域不会被放大裁掉。

所有写命令都要求逐次确认。程序同时检查当前连接必须是 CAN1，并按固件规则检查主控状态；没有收到主控状态时禁止发送配置和故障复位命令。

## Windows 源码运行

1. 安装 PEAK PCAN 驱动和 PCAN-Basic。确认 PCAN-View 能以正确位率打开设备。
2. Windows 10/11 应安装 Microsoft Edge WebView2 Runtime。多数系统已经预装。
3. 在项目根目录执行：

```powershell
py -3.11 -m venv .venv-bms-host
.\.venv-bms-host\Scripts\Activate.ps1
python -m pip install -r TOOLS\bms_host\requirements.txt
python -m TOOLS.bms_host
```

开发界面时可加 `--debug`。没有 PCAN 时，连接窗口选择“内置模拟数据”，可以检查全部界面和写命令流程。

## 构建 Windows 程序

```powershell
powershell -ExecutionPolicy Bypass -File TOOLS\bms_host\build_windows.ps1
```

产物位于 `dist\BITFSAE_BMS_Control_Desk\`。当前采用 one-folder 形式，便于确认 WebView 和 PCAN 依赖；发布前必须在目标 Windows 电脑上完成本文末尾的硬件检查。

## 界面分工和操作顺序

### 运行总览

总览用于在一个窗口内快速判断当前能否继续测试或充电，显示顺序如下：

1. 状态机、告警等级、统一故障码、活动告警数、充电/放电模式和本机时间。
2. 包电压、总电流、PRE电压、单体压差和SOC。
3. 主正、主负、预充继电器意向位，HV_ACC、实体充电信号、安全回路、预充耗时和继电器总输出。
4. 六个模组的平均电压、平均温度、模组压差和数据状态。
5. 温度极值、温差、风扇占空比/转速、IMD状态和绝缘阻值。
6. 最近约两分钟的包电压和总电流曲线。
7. 本次充电计时、预计剩余时间、预计充满时刻和用于估算的平均充电电流。
8. 当前故障和告警的简短解析；完整32项结果在“故障与记录”页查看。

安全回路显示来自告警bit22“安全回路断开”。继电器显示的是主控周期报文中的命令/意向状态，不代表接触器辅助触点已经确认。当前硬件没有完整辅助触点反馈时，不能仅凭界面“闭合”判断主回路物理闭合。

六个模组的平均电压只使用本模块当前有效的23串；平均温度只使用当前有效的8路。模组压差是本模块有效单体的最高值减最低值。缺失值不参与平均，但模组状态会显示数据缺失。

充电计时从上位机首次检测到主控`charge_mode=1`开始，不追溯程序启动前已经进行的充电。状态帧超时时暂停累计，充电模式退出后保留本次最终计时，再次进入充电模式时重新开始。预计剩余时间按当前26E配置的16.2Ah容量、主控SOC和本次监视期间有效充电电流的平均值计算：

```text
剩余容量 = 16.2 Ah × (100% - SOC)
预计剩余时间 = 剩余容量 ÷ 本次平均充电电流
```

预计结果不包含充电末段降流、充电机限流、温度保护、均衡和中途暂停，只用于现场安排时间，不能作为充电完成判据。电流不高于0.1A、状态帧超时、非充电模式或数据无效时不显示预计时间。历史回放也不按本机时间估算充满时刻。

### 电芯与温度

页面按BMU1..BMU6排列，每个模组同时显示23串电压和8路温度。电压区和温度区由数据自身的`C`、`T`编号及列位置区分，不再额外占一行重复写“电压”“温度”。单路编号在模组内使用`C1..C23`和`T1..T8`，不重复显示没有现场定位价值的全局三位编号。顶部用较大字号显示全包电压/温度极值，保护阈值单独成组显示主控当前回报的过压、欠压、过温和低温值。数据全部有效时不显示完整性文字；存在缺失时，顶部和对应模组标题才显示缺失数量。

电压第0帧的Byte0..1为保留字段，Byte2..7对应前三串；第1..5帧各含四串。温度显示值是从控CAN温度码减30。主控内部还会应用`tempoffset[]`，因此偏移不为0时，逐路原始温度可能和主控上报的温度极值不同。

任一电压帧存在500..5000mV之外的数据、温度码大于129或DLC不足时，该帧对应数据标为无效。`0xFFFF`电压和`0xFF`温度显示为断线；超过750ms未更新显示为过期。页面颜色按当前阈值即时分类，只用于定位，不代替主控的延时告警结果。

“只看异常 / 缺失”同时检查电压和温度。一个模组两类数据都正常时隐藏整个模组；全部正常时只显示一次正常结果。

### 故障与记录

本页全部为读取和显示操作：

- 32项告警显示名称、当前判定条件、阈值或时限和当前等级。单体四项阈值使用主控周期回报；包电压、压差、温差、SOC、持续过流和通信时间使用当前F405程序中的固定规则。
- bit编号只保留在鼠标悬停提示和协议文档中；日常监视页面不再在同一项内重复显示编号。
- 尚未收到告警等级帧或保护开关帧时显示“等待等级/等待回报”，不会把初始零值误显示成正常或关闭。
- “只看活动项”保留一级、二级或`fault_code`置位的项目。
- 19个保护/蜂鸣器开关用“启用/关闭”、颜色和汇总数量显示主控当前回报，不在本页修改。
- 故障码变化记录保存本次会话最近200次进入和清除；历史回放会按回放位置重建。
- “读取最近50条”查询Flash重要故障日志。读取只允许自检、待机或故障保持态，不会修改Flash内容。

### CAN监视器

搜索支持CAN ID、帧名和数据文本。方向筛选可选全部、接收或发送；暂停列表只冻结当前表格，不停止CAN接收和数据记录。报文表在窗口剩余区域内独立滚动，搜索和记录操作始终保留在上方。

### 参数与命令

所有会改变主控参数或状态的操作集中在本页。顶部三个条件分别表示CAN1已连接、主控处于允许状态和状态帧未超时。每次发送前仍会打开独立确认窗口，显示通道、总线、主控状态、告警等级和命令名；必须勾选本次确认才能发送。

| 操作 | 主控处理条件 | 结果确认 |
|---|---|---|
| 四项单体阈值 | 自检、待机或故障保持；参数范围及高低关系合法 | 统一应答，随后看周期回报 |
| 19个告警/蜂鸣器开关 | 自检、待机或故障保持 | 整组写入；Debug/Release会恢复基础保护 |
| 充电请求 | 自检、待机或故障保持；415.4..578.2V、0..4.5A | 统一应答及主控当前回报 |
| 电流方向、充电机类型 | 自检、待机或故障保持 | 统一应答、周期回读和Flash保存状态 |
| RTC校时 | 已连接CAN1 | 独立RTC应答和主控回读时间 |
| 清除Flash日志 | 自检、待机或故障保持 | 分阶段清除状态；不清实时故障 |
| 故障保持复位 | 主控处于故障保持 | 主控继续检查实时告警和HV_ACC |

PCAN发送成功只说明报文已交给驱动。除RTC外的版本3写命令还必须在1秒内收到请求计数和命令码一致的`0x18A650F4`统一应答。主控拒绝、应答超时或命令码不一致都显示失败。

## 界面刷新和PyWebView

CAN接收在独立线程运行。总览在上一次状态读取完成250ms后再读，其他页面使用500ms，窗口隐藏时使用1000ms；不会同时发起多个状态读取。每轮只更新当前页面需要的内容。

`Api`中的CAN服务和原生窗口引用必须保持为以下划线开头的私有成员。PyWebView会递归扫描公开成员；公开WinForms窗口会遍历`AccessibilityObject`，可能出现`TYPE_E_CANTLOADLIBRARY`和递归深度溢出并导致界面卡死。自动测试会检查API对象没有公开状态成员。

## 数据记录、回放和工程文件

`.bmslog` 是 SQLite 单文件，包含格式版本、总线用途、通道、位率和按顺序保存的原始 CAN 帧。程序每100帧或最长约0.5秒提交一次，兼顾长时间记录性能和异常退出时的数据保留。回放按时间从数据库分段读取，不把完整长时间记录一次载入内存；拖动时读取目标前约130秒的普通帧，并单独重建此前的故障码变化和一次性应答。CSV 每帧刷新，便于直接查看，但长时间高帧率记录的性能低于 `.bmslog`，且回放最多载入200万帧。

`.bmsproj` 是 UTF-8 JSON 工程文件，不包含大体积 CAN 数据。工程文件和数据记录分开，避免修改参数时复制整段历史数据，也避免工程在不同电脑间移动时保存失效的绝对日志路径。

程序运行时不依赖外部DBC。当前公共仓库`vehicle-interfaces`尚未同步F405的风扇字段、版本2故障帧、版本3告警开关、运行/固件/IVT诊断、版本3工具命令和统一应答，直接作为运行时解析源会丢失数据或造成误判。协议同步完成后，可以再评估用公共DBC生成部分普通信号定义；动态从控ID、工具命令状态限制和写入确认仍应由本程序显式处理。

## 台架和实车检查

1. 先只连接 CAN1 和低压供电，主控保持待机；对照 PCAN-View 检查扩展帧 ID、DLC 和位率。
2. 对六个从控逐一断开通信，确认页面在 350 ms 左右显示对应帧缺失，并核对主控 `slave_offline` 位。
3. 用可控电源或从控台架逐路检查 138 串编号；特别确认每个从控第 1 帧从 Byte2 开始，以及模块交界的 23/24、46/47、69/70、92/93、115/116 串。
4. 检查 48 路温度编号。页面显示 CAN1 上从控发送的温度码减 30；主控内部还会应用 `tempoffset[]`，若偏移不全为 0，单路页面值与主控极值可能不同。
5. 写配置前记录旧值，只在自检、待机或故障保持态发送；等待下一个周期回报并断电重启，确认 Flash 保存结果。
6. 充电台架先用 0 A 请求验证报文和状态，再逐步增加电流。监视最高单体、最高温度、电流、SOP、IMD 和全部告警。
7. 故障复位只在高压已断开、HV_ACC 释放且实时故障消失后测试。Flash 日志清除应单独验证，不能用它代替故障复位。
