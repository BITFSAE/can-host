# BITFSAE BMS Control Desk

这是 F405 BMS 主控的 CAN 上位机，主要面向 Windows（PCAN-USB），macOS 上可以源码运行并直接使用内置模拟数据。程序默认连接 PCAN-USB 的 CAN1，也支持 CANB 500 kbit/s、Legacy CANB 250 kbit/s，以及不接硬件的内置模拟数据。

## 已实现功能

- 运行总览：集中显示主控状态、高压链路、六个模组摘要、独立的温度与冷却卡片、独立的 IMD 卡片、趋势曲线和充电计时；具体显示顺序和字段见下方“运行总览”。当前不显示 SOP。
- 电芯与温度：按六个从控的物理顺序，在同一页面同时显示138串电压和48路温度；顶部显示当前四项阈值和全包极值，每个模组显示电压范围、压差和温度范围。正常数据不反复标注完整性，只有通信中断或数据缺失时才显示醒目提示。
- 故障与记录：只读显示32项告警、统一故障码、19个保护开关当前回报、故障码变化和Flash重要故障日志。每项告警直接显示当前阈值、固定判定条件和确认时间，不在主界面重复显示bit编号。
- 参数与命令：所有写入集中在一个独立页面，包括四项阈值、19个开关、充电请求、电流方向、充电机类型、RTC校时、日志清除和故障复位。写命令必须收到请求计数和命令码一致的主控应答。
- CAN 监视器：查看最近 320 帧，按方向或文本筛选；默认记录为单文件 `.bmslog`，也可导出兼容表格工具的 CSV。两种文件都能重新打开，并按 0.25..10 倍速度播放、暂停和拖动时间位置，全部状态页面随历史帧恢复。
- 故障历史：把 `fault_code` 每次增加和清除的位解析为中文故障项，记录变化前后故障码和时间；实时会话与历史回放使用同一套显示。
- CANB：解析统一故障帧、告警等级、SOP、IVT-S结果、Legacy充电反馈及放电总状态。CANB没有从控单体原始帧，因此不能显示完整138串和48路温度；SOP和IVT原始数据保留在CAN监视器、记录和后台解析中，当前总览不单独设置面板。
- 界面：监视与写入操作分区；绿色表示正常，黄色表示二级告警，红色表示一级故障、无效数据或危险操作，青色只用于交互。总览按“安全状态优先、卡片主题单一、状态值醒目、只保留现场需要的信息”组织：状态机使用“标题在上、当前状态在下”的纵向结构，并按 `SELF_TEST`、`STANDBY`、`PRECHARGE`、`HV_ON`、`FAULT` 显示；三路继电器用等宽状态格直接显示，温度/冷却和 IMD 使用两个独立卡片，充电计时只显示已计时和预计剩余。参数页按内容压缩面板高度，系统参数与谨慎操作使用左右两个同级面板；Flash 保存状态放在顶部命令条件栏，写入后无需滚动即可看到。底部状态栏所有信息保持单行：连接项显示 PCAN 通道、总线用途和位率，旁边显示 RX/TX、固件身份和记录状态；左侧保留上位机版本/日期和硬件 PCB 版本/日期。页面不再设置统一标题和解释栏。`Alt+1..4`切换四个监视页，`Alt+5`进入参数与命令页。默认缩放为110%；`Ctrl++`放大、`Ctrl+-`缩小、`Ctrl+0`恢复默认110%，也支持`Ctrl+鼠标滚轮`。缩放范围为80%..130%，关闭后会记住当前比例；程序会同步修正可视高度，底部状态栏和页面滚动区域不会被放大裁掉。

所有写命令都要求逐次确认。程序同时检查当前连接必须是 CAN1，并按固件规则检查主控状态；没有收到主控状态时禁止发送配置和故障复位命令。

## 上位机界面设计原则

总览面向现场快速判断，不追求把所有后台数据同时铺开：

1. 先看安全状态和故障，再看包电压、电流、压差、SOC 等关键量，最后看模块、温度、趋势和辅助诊断。
2. 每个卡片只表达一个主题。温度/冷却和 IMD 分开；继电器命令直接用三格显示；字段已经能说明含义时不再增加小标题。状态机使用纵向标题和醒目的当前状态值，与其他卡片使用相同的边框和间距，不添加彩色侧边条或单独的装饰样式。
3. 卡片大小服从内容数量。小量信息使用紧凑状态格，禁止出现大面积空白配小字号文字；状态值比说明文字更醒目。
4. 只在总览保留会影响当前判断的字段。内部计算用的平均电流、预计完成时刻等信息不直接堆在充电计时卡片中。
5. 正常状态保持安静，故障和危险操作使用明确的颜色与字重；超时、无效和未收到数据必须显示为等待或无效，不能用零值代替。
6. 鼠标悬浮提示只补充短的字段解释、英文缩写或协议名称，不显示实现细节、异常兜底过程或大段文档。
7. 修改布局后必须检查最小窗口、放大比例、正常状态和故障状态，确保字号、对齐、滚动和状态颜色都能被实际操作者快速识别。

## 版本日期和底部状态信息

- 上位机版本 `0.1.0` 和“上位机版本日期”由 `TOOLS/bms_host/__init__.py` 维护。日期表示这份上位机版本的发布日期/维护日期，不是电脑当前时间，也不是上位机实际打包时间。
- 固件构建日期来自 F405 的 `0x186C51F4` 帧。固件在 CMake 配置/构建时按北京时间（UTC+8）记录年、月、日，上位机显示“构建 YYYY-MM-DD”。它表示固件产物的构建日期，不表示固件协议版本日期。
- 固件身份显示 `Debug`、`Release` 或 `Debug-Bringup` 构建变体、12 位 Git 提交标识和构建日期；构建工作区是否有未提交改动不在界面显示。
- 底部不再显示“状态帧 0.1 s”这类内部计时。上位机仍在后台记录最近一次 `0x187650F4` 主控统一故障状态帧的接收时间，并在超过 1.5 s 时认为状态已超时；该判断继续用于总览提示、充电计时暂停和写命令条件检查。

## Windows 源码运行

1. 安装 PEAK PCAN 驱动和 PCAN-Basic。确认 PCAN-View 能以正确位率打开设备。
2. Windows 10/11 应安装 Microsoft Edge WebView2 Runtime。多数系统已经预装。
3. 在项目根目录执行：

```powershell
py -3.11 -m venv .venv-bms-host
.\.venv-bms-host\Scripts\Activate.ps1
python -m pip install -r TOOLS\bms_host\requirements.txt
python -m TOOLS.bms_host
```

开发界面时可加 `--debug`。源码运行没有 PCAN 时，连接窗口可以选择“内置模拟数据”检查界面和写命令流程；这个选项只用于源码开发，不进入 Windows 发布版。

内置模拟数据按“待机 → 预充 → 高压充电”的约 90 秒循环演示状态机：预充阶段 PRE 电压从 0 爬升到包电压，最后 30 秒置 `charge_mode=1` 并发送正向充电电流，便于检查继电器、预充耗时、充电计时、预计剩余和趋势曲线。

## macOS 源码运行

macOS 上同样支持源码运行，主要用于界面开发和内置模拟数据调试：

```bash
cd /Users/poli/STM32CubeIDE/workspace_2.1.1/BMS_MASTER_F405
python3 -m venv .venv-bms-host
.venv-bms-host/bin/python -m pip install -r TOOLS/bms_host/requirements.txt
```

窗口使用系统 WebKit 渲染，文件对话框使用原生 macOS 对话框。连接窗口中的 PCAN 通道按 Windows 驱动设计，本机没有 PEAK macOS 驱动，只能使用“内置模拟数据”；需要实体 CAN 时请在 Windows 电脑上运行。开发界面时可加 `--debug`。

```powershell
powershell -ExecutionPolicy Bypass -File TOOLS\bms_host\build_windows.ps1
```

产物位于 `dist\BITFSAE_BMS_Control_Desk\`。当前采用 one-folder 形式，发布版只连接真实 PCAN，连接窗口不显示工作模式和内置模拟数据选项；模拟器模块也不打包。

### Windows 发布版使用

将整个 `BITFSAE_BMS_Control_Desk` 文件夹复制到目标 Windows 电脑，双击其中的 `BITFSAE_BMS_Control_Desk.exe` 即可启动。目标电脑不需要安装 Python、虚拟环境、pip、pywebview 或项目源码，不能只单独复制 exe 文件。

目标电脑仍需要两个系统组件：

1. PEAK PCAN-USB 驱动及 PCAN-Basic 运行组件，用于识别 PCAN 设备和打开 CAN1/CANB。
2. Microsoft Edge WebView2 Runtime，用于显示程序界面；Windows 10/11 多数已预装，缺少时先安装 Evergreen Runtime。

发布版连接窗口直接选择 PCAN 通道和总线用途，程序内部固定使用真实 PCAN。CAN1 是可写主控总线，CANB 和 Legacy CANB 只读；没有 PCAN 设备或驱动时，连接会失败并显示原因。内置模拟数据只保留在源码运行路径中，供开发和自动化验证使用。

## 界面分工和操作顺序

### 运行总览

总览用于在一个窗口内快速判断当前能否继续测试或充电，显示顺序如下：

1. 状态机（`SELF_TEST`、`STANDBY`、`PRECHARGE`、`HV_ON`、`FAULT`）、告警等级、统一故障码、活动告警数、充电/放电模式和本机时间。
2. 包电压、总电流、PRE电压、单体压差和SOC。
3. 高压输出状态、三路继电器控制命令、HV_ACC上高压请求、充电按钮、外部安回中断事件、BMS故障信号Q3和最近一次预充。
4. 六个模组的平均电压、平均温度、模组压差和数据状态。
5. 温度与冷却卡片显示温度极值、温差、风扇目标占空比/转速/停转诊断；IMD 使用独立卡片显示 `OK_HS`（PB8，正常/故障）、实际 PWM 频率、占空比和解析出的绝缘阻值。DCP、SST 等简短模式说明放在字段悬浮提示中。
6. 最近约两分钟的包电压、总电流和 PRE 电压三线曲线。
7. 充电计时只显示本次已计时和预计剩余时间；预计剩余时间按当前SOC和本次有效充电电流估算。
8. 当前故障和告警的简短解析；完整32项结果在“故障与记录”页查看。

高压卡片直接显示三路继电器和请求/安全状态，不再为“继电器控制命令”“请求与安全回路”等已经能由字段名称说明的内容增加小标题。继电器显示主控发出的控制命令，HV_ACC是整条外部安全回路最后送到主控的上高压请求，`CHG_GUN`是主控已知的充电按钮，Q3是 BMS 故障信号。告警 bit22 显示为“外部安回中断事件”：它表示预充或高压过程中 HV_ACC 请求被释放，且不是 Q3 已知故障、充电按钮释放或 IMD PB8 数字故障造成的；Q3 导致的后续 HV_ACC 释放不显示为 bit22。这个事件可能由急停、插头互锁、驾驶员开关或其他外部节点动作引起，但主控只能确认 HV_ACC 请求消失，无法区分具体是哪一个节点。继电器显示的是主控命令，不是接触器真实反馈，因此界面显示“闭合”不等于主回路已经确认闭合。

参数页的充电请求区分两个值：`请求值`是主控保存并下发的请求电压/电流，来自 `0x186350F4` 的 `ChrReqVolt`、`ChrReqCurr`；`充电机反馈`是 Legacy 或 Chroma 充电机返回的实际电压/电流，来自主控运行诊断和对应 CANB 充电反馈链路。IVT 数据在协议解析中独立保存，不与这两个充电机字段混用。反馈未收到或已过期时显示“等待反馈”或“反馈超时”。

故障状态、告警等级、继电器命令、温度/风扇和 IMD 各自按最近 1.5 s 的对应报文判断新鲜度。报文未收到或超过 1.5 s 时显示“等待数据”，不会把启动默认值或上一条旧值当作当前状态；趋势图也不再为失联后的 PRE 电压追加新点。

温度与冷却卡片把温度、风扇控制命令和转速诊断放在一起；“风扇目标占空比”只表示主控要求风扇转动，“风扇诊断”才结合转速判断风扇是否真正转动。IMD 使用独立卡片：`OK_HS` 直接显示正常或故障，PWM 显示实际频率，下面显示占空比和绝缘阻值。10/20Hz 为 DCP 阻值解析模式，30Hz 为 SST 模式；这些名称只在需要时通过悬浮提示补充。IMD 显示和 BMS 故障信号 Q3 是两条独立路径，IMD 软件诊断不会自动显示成 Q3。

六个模组的平均电压只使用本模块当前有效的23串；平均温度只使用当前有效的8路。模组压差是本模块有效单体的最高值减最低值。缺失值不参与平均，但模组状态会显示数据缺失。

充电计时从上位机首次检测到主控`charge_mode=1`开始，不追溯程序启动前已经进行的充电。状态帧超时时暂停累计，充电模式退出后保留本次最终计时，再次进入充电模式时重新开始。界面只显示已计时和预计剩余时间；预计剩余时间按当前26E配置的16.2Ah容量、主控SOC和本次监视期间有效充电电流的平均值计算：

```text
剩余容量 = 16.2 Ah × (100% - SOC)
预计剩余时间 = 剩余容量 ÷ 本次平均充电电流
```

预计结果不包含充电末段降流、充电机限流、温度保护、均衡和中途暂停，只用于现场安排时间，不能作为充电完成判据。电流不高于0.1A、状态帧超时、非充电模式或数据无效时不显示预计时间。历史回放也不按本机时间估算充满时刻。

### 电芯与温度

页面按BMU1..BMU6排列，每个模组同时显示23串电压和8路温度。电压区和温度区由数据自身的`C`、`T`编号及列位置区分，不再额外占一行重复写“电压”“温度”。单路编号在模组内使用`C1..C23`和`T1..T8`，不重复显示没有现场定位价值的全局三位编号。顶部用较大字号显示全包电压/温度极值，保护阈值单独成组显示主控当前回报的过压、欠压、过温和低温值。数据全部有效时不显示完整性文字；存在缺失时，顶部和对应模组标题才显示缺失数量。

电压第0帧的Byte0..1为保留字段，Byte2..7对应前三串；第1..5帧各含四串。温度显示值是从控CAN温度码减30。主控内部还会应用`tempoffset[]`，因此偏移不为0时，逐路原始温度可能和主控上报的温度极值不同。

任一电压帧存在500..5000mV之外的数据、温度码大于129或DLC不足时，该帧对应数据标为无效。`0xFFFF`电压和`0xFF`温度显示为断线；超过750ms未更新显示为过期。页面颜色按当前阈值即时分类，只用于定位，不代替主控的延时告警结果。

“只看异常 / 缺失”同时检查电压和温度。一个模组两类数据都正常时隐藏整个模组；全部正常时只显示一次正常结果。

### 故障与记录

本页全部为读取和显示操作：

- 32项告警显示名称、当前判定条件、阈值或时限和当前等级。单体四项阈值使用主控周期回报；包电压、压差、温差、SOC、持续过流和通信时间使用当前F405程序中的固定规则。
- bit编号只保留在鼠标悬停提示和协议文档中；日常监视页面不再在同一项内重复显示编号。
- 尚未收到告警等级帧或保护开关帧时显示“等待等级/等待回报”，不会把初始零值误显示成正常或关闭。
- “只看活动项”保留一级、二级或`fault_code`置位的项目。
- 19个保护/蜂鸣器开关用“启用/关闭”、颜色和汇总数量显示主控当前回报；每项同时显示 DOC 中的短名（如 `ov`、`chgocs`、`ivtloss`），完整变量名放在悬浮提示中。
- 故障码变化记录保存本次会话最近200次进入和清除；历史回放会按回放位置重建。
- “读取最近50条”查询Flash重要故障日志。读取只允许自检、待机或故障保持态，不会修改Flash内容。

### CAN监视器

搜索支持CAN ID、帧名和数据文本。方向筛选可选全部、接收或发送；暂停列表只冻结当前表格，不停止CAN接收和数据记录。报文表在窗口剩余区域内独立滚动，搜索和记录操作始终保留在上方。

### 参数与命令

所有会改变主控参数或状态的操作集中在本页。顶部三个条件分别表示CAN1已连接、主控处于允许状态和状态帧未超时。每次发送前仍会打开独立确认窗口，显示通道、总线、主控状态、告警等级和命令名；必须勾选本次确认才能发送。

| 操作 | 主控处理条件 | 结果确认 |
|---|---|---|
| 四项单体阈值 | 自检、待机或故障保持；参数范围及高低关系合法 | 统一应答，随后看周期回报和 Flash 保存状态 |
| 19个告警/蜂鸣器开关 | 自检、待机或故障保持 | 整组写入；Debug/Release会恢复基础保护，并在保存等待位清除后显示已保存 |
| 充电请求 | 自检、待机或故障保持；415.4..578.2V、0..4.5A | 统一应答、请求值回读和充电机反馈 |
| 电流方向、充电机类型 | 自检、待机或故障保持 | 统一应答、周期回读和Flash保存状态 |
| RTC校时 | 已连接CAN1 | 独立RTC应答和主控回读时间 |
| 清除Flash日志 | 自检、待机或故障保持 | 分阶段清除状态；不清实时故障 |
| 故障保持复位 | 主控处于故障保持 | 主控继续检查实时告警和HV_ACC |

PCAN发送成功只说明报文已交给驱动。除RTC外的版本3写命令还必须在1秒内收到请求计数和命令码一致的`0x18A650F4`统一应答。主控拒绝、应答超时或命令码不一致都显示失败。收到“等待保存”后，界面继续读取主控的周期保存状态：仍在保存时显示“等待 Flash 保存”，保存等待位清除后显示“已保存到 Flash”；Flash 不可用或长时间未完成时显示明确提示。这个提示确认的是主控已完成保存流程，不是单纯的报文发送成功。

## 界面刷新和PyWebView

CAN接收在独立线程运行。总览在上一次状态读取完成250ms后再读，其他页面使用500ms，窗口隐藏时使用1000ms；不会同时发起多个状态读取。每轮只更新当前页面需要的内容。

`Api`中的CAN服务和原生窗口引用必须保持为以下划线开头的私有成员。PyWebView会递归扫描公开成员；公开WinForms窗口会遍历`AccessibilityObject`，可能出现`TYPE_E_CANTLOADLIBRARY`和递归深度溢出并导致界面卡死。自动测试会检查API对象没有公开状态成员。

## 数据记录与回放

`.bmslog` 是 SQLite 单文件，包含格式版本、总线用途、通道、位率和按顺序保存的原始 CAN 帧。程序每100帧或最长约0.5秒提交一次，兼顾长时间记录性能和异常退出时的数据保留。回放按时间从数据库分段读取，不把完整长时间记录一次载入内存；拖动时读取目标前约130秒的普通帧，并单独重建此前的故障码变化和一次性应答。CSV 每帧刷新，便于直接查看，但长时间高帧率记录的性能低于 `.bmslog`，且回放最多载入200万帧。

程序运行时不依赖外部DBC。当前公共仓库`vehicle-interfaces`尚未同步F405的风扇字段、版本2故障帧、版本3告警开关、运行/固件/IVT诊断、版本3工具命令和统一应答，直接作为运行时解析源会丢失数据或造成误判。协议同步完成后，可以再评估用公共DBC生成部分普通信号定义；动态从控ID、工具命令状态限制和写入确认仍应由本程序显式处理。

## 台架和实车检查

1. 先只连接 CAN1 和低压供电，主控保持待机；对照 PCAN-View 检查扩展帧 ID、DLC 和位率。
2. 对六个从控逐一断开通信，确认页面在 350 ms 左右显示对应帧缺失，并核对主控 `slave_offline` 位。
3. 用可控电源或从控台架逐路检查 138 串编号；特别确认每个从控第 1 帧从 Byte2 开始，以及模块交界的 23/24、46/47、69/70、92/93、115/116 串。
4. 检查 48 路温度编号。页面显示 CAN1 上从控发送的温度码减 30；主控内部还会应用 `tempoffset[]`，若偏移不全为 0，单路页面值与主控极值可能不同。
5. 写配置前记录旧值，只在自检、待机或故障保持态发送；等待下一个周期回报并断电重启，确认 Flash 保存结果。
6. 充电台架先用 0 A 请求验证报文和状态，再逐步增加电流。监视最高单体、最高温度、电流、SOP、IMD 和全部告警。
7. 故障复位只在高压已断开、HV_ACC 释放且实时故障消失后测试。Flash 日志清除应单独验证，不能用它代替故障复位。
