# BITFSAE BMS Control Desk

这是 F405 BMS 主控的 Windows CAN 上位机。程序默认连接 PCAN-USB 的 CAN1，也支持 CANB 500 kbit/s、Legacy CANB 250 kbit/s，以及不接硬件的内置模拟数据。

## 已实现功能

- 运行总览：包电压、电流、SOC、状态、告警等级、单体极值、SOP、IMD、高压输入、继电器、预充结果，以及固件变体/Git身份。
- 单体监视：按六个从控的物理顺序显示 138 串电压和 48 路温度，显示缺帧、过期和断线值；每个从控单独显示 6 帧电压、1 帧温度的完整性。
- 告警与配置：解析32项告警等级和32位实时故障码；读取并修改4项单体阈值及CAN协议包含的19个告警/蜂鸣器开关。
- 充电与维护：读取请求值和带500ms新鲜度的充电机反馈；修改充电请求、方向和充电机类型；RTC校时；读取最近50条Flash重要故障日志；请求清除日志或复位故障保持。版本3写命令必须收到请求计数和命令码都一致的主控应答；分阶段清除日志期间禁用再次清除和日志读取。
- CAN 监视器：查看最近 320 帧，按方向或文本筛选；默认记录为单文件 `.bmslog`，也可导出兼容表格工具的 CSV。两种文件都能重新打开，并按 0.25..10 倍速度播放、暂停和拖动时间位置，全部状态页面随历史帧恢复。
- 故障历史：把 `fault_code` 每次增加和清除的位解析为中文故障项，记录变化前后故障码和时间；实时会话与历史回放使用同一套显示。
- 工程导入导出：`.bmsproj`保存总线用途和PCAN通道、阈值、19个告警开关、充电请求、电流方向、充电机类型、工程说明和页面偏好。导入只填充界面，不会自动连接或写主控。
- CANB：解析统一故障帧、告警等级、SOP、IVT-S 结果、Legacy 充电反馈及放电总状态。CANB 上没有从控单体原始帧，因此连接 CANB 时单体页面不会出现 138 串实时数据。

所有写命令都要求逐次确认。程序同时检查当前连接必须是 CAN1，并按固件规则检查主控状态；没有收到主控状态时禁止发送配置和故障复位命令。

## Windows 源码运行

1. 安装 PEAK PCAN 驱动和 PCAN-Basic。确认 PCAN-View 能以正确位率打开设备。
2. Windows 10/11 应安装 Microsoft Edge WebView2 Runtime。多数系统已经预装。
3. 在项目根目录执行：

```powershell
py -3.11 -m venv .venv-bms-host
.\.venv-bms-host\Scripts\Activate.ps1
python -m pip install -r TOOLS\bms_host\requirements.txt
python -m TOOLS.bms_host
```

开发界面时可加 `--debug`。没有 PCAN 时，连接窗口选择“内置模拟数据”，可以检查全部界面和写命令流程。

## 构建 Windows 程序

```powershell
powershell -ExecutionPolicy Bypass -File TOOLS\bms_host\build_windows.ps1
```

产物位于 `dist\BITFSAE_BMS_Control_Desk\`。当前采用 one-folder 形式，便于确认 WebView 和 PCAN 依赖；发布前必须在目标 Windows 电脑上完成本文末尾的硬件检查。

## 代码结构

| 文件 | 作用 |
|---|---|
| `protocol.py` | 按当前 F405 固件解析报文、检查范围并生成工具命令 |
| `can_service.py` | PCAN 接收线程、发送、状态保护、`.bmslog`/CSV记录和历史回放 |
| `simulator.py` | 138S/48T 模拟数据与命令回报 |
| `app.py` | PyWebView 原生窗口和前后端接口 |
| `web/` | 无网络依赖的 HTML/CSS/JavaScript 界面 |
| `Tests/test_bms_host_protocol.py` | 映射、解析、编码及模拟链路测试 |

`.bmslog` 是 SQLite 单文件，包含格式版本、总线用途、通道、位率和按顺序保存的原始 CAN 帧。程序每100帧或最长约0.5秒提交一次，兼顾长时间记录性能和异常退出时的数据保留。回放按时间从数据库分段读取，不把完整长时间记录一次载入内存；拖动时读取目标前约130秒的普通帧，并单独重建此前的故障码变化和一次性应答。CSV 每帧刷新，便于直接查看，但长时间高帧率记录的性能低于 `.bmslog`，且回放最多载入200万帧。

`.bmsproj` 是 UTF-8 JSON 工程文件，不包含大体积 CAN 数据。工程文件和数据记录分开，避免修改参数时复制整段历史数据，也避免工程在不同电脑间移动时保存失效的绝对日志路径。

程序运行时不依赖外部DBC。当前公共仓库`vehicle-interfaces`尚未同步F405的风扇字段、版本2故障帧、版本3告警开关、运行/固件/IVT诊断、版本3工具命令和统一应答，直接作为运行时解析源会丢失数据或造成误判。协议同步完成后，可以再评估用公共DBC生成部分普通信号定义；动态从控ID、工具命令状态限制和写入确认仍应由本程序显式处理。

## 台架和实车检查

1. 先只连接 CAN1 和低压供电，主控保持待机；对照 PCAN-View 检查扩展帧 ID、DLC 和位率。
2. 对六个从控逐一断开通信，确认页面在 350 ms 左右显示对应帧缺失，并核对主控 `slave_offline` 位。
3. 用可控电源或从控台架逐路检查 138 串编号；特别确认每个从控第 1 帧从 Byte2 开始，以及模块交界的 23/24、46/47、69/70、92/93、115/116 串。
4. 检查 48 路温度编号。页面显示 CAN1 上从控发送的温度码减 30；主控内部还会应用 `tempoffset[]`，若偏移不全为 0，单路页面值与主控极值可能不同。
5. 写配置前记录旧值，只在自检、待机或故障保持态发送；等待下一个周期回报并断电重启，确认 Flash 保存结果。
6. 充电台架先用 0 A 请求验证报文和状态，再逐步增加电流。监视最高单体、最高温度、电流、SOP、IMD 和全部告警。
7. 故障复位只在高压已断开、HV_ACC 释放且实时故障消失后测试。Flash 日志清除应单独验证，不能用它代替故障复位。
