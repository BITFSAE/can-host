# BMS Control Desk 进度、待办与变更

本文档记录 CAN 上位机的剩余工作、风险、验证结果和已完成变更。原 `CHANGELOG.md` 的内容已经并入文末“已完成变更”节，本目录只保留这一份进度文件，不再单独维护 changelog。上位机进度、风险和验证以本文件为准，不在根目录 `todo.md` 重复登记；只有影响 F405 固件协议、安全行为或跨层联调的结论，才由根目录 `todo.md` 记录固件侧摘要。使用者说明见 [`../../DOC/CAN上位机与工具使用.md`](../../DOC/CAN上位机与工具使用.md)，安装和发布见 [`README.md`](README.md)。

## 当前状态

- CAN1、CANB 500 kbit/s、Legacy CANB 250 kbit/s和内置模拟数据已经接入。
- 已实现138串电压、48路温度、主控总览、故障与记录、独立参数与命令页、CAN记录/回放；高压、温度/冷却和 IMD 已按现场判断顺序分成直接可读的卡片。使用字段和页面顺序见 [`../../DOC/CAN上位机与工具使用.md`](../../DOC/CAN上位机与工具使用.md)。
- 在线写命令逐次确认，并核对总线、主控状态、请求计数、命令码和统一应答。
- 台架模拟从控和 IVT 配置已经拥有独立页面、独立连接和独立服务；默认收在“工程工具”折叠项中，不再通过底部连接方式切换。台架固定向 F405 CAN1 发送从控帧；真实 IVT-S 接 F405 CANB，台架不发送 `0x512`。
- 已同步 F405 协议版本4：所有工具请求使用 `0x18A050F5`、固定 DLC=8；CANB BMS 状态/故障/告警使用 `0x4B0/0x4B1/0x4B2`，`0x401/0x402` 只按 Chroma 厂商报文解析；`0x186050F4` 按有符号电流和有效位解析。无效或不完整的单体/温度极值不再显示为占位值或旧值；总览不再把故障帧当作总状态帧，状态帧过期或有效位为 0 时显示“等待数据”；后台写命令也拒绝没有新鲜总状态帧的发送。
- 工具页保留脚本的常用场景和命令输入；IVT 先读回并自动尝试出厂/目标 ID，再显示“已配置且一致”“未配置”或“配置不符”，一次性配置和 250/500 kbit/s 过渡操作分开显示。
- 主监视连接仍位于底部状态栏，只负责 BMS 上位机；工具页有自己的 PCAN 通道和连接按钮，支持主监视、台架和 IVT 分别维护状态。

## 已完成变更

### 2026-08-04

#### P2 台架、P3 IVT 配置与页面拆分

- 主上位机连接窗口增加“CAN1 从控台架”。台架只发送 138 串/48 路从控帧，真实 IVT-S 接 F405 CANB，不打开第二通道，也不发送 `0x512`。
- 主上位机增加独立“PCAN 从控台架”页面，场景按钮和命令输入复用 `pcan_bms_bench.py` 的 `BenchModel` / `CommandProcessor`。
- 新增 ivt.py，统一 IVT 请求、响应解析、BMS CANB 目标配置和读回比较。IVT 应答由 CanService 的接收线程分发，配置操作不再另开 recv。
- CANB 允许的写操作限定为真实 PCAN 上的 IVT 命令；CAN1 F405 工具命令、模拟数据和历史回放边界保持不变。
- 主上位机增加独立“IVT 配置”页面。配置会写入 8 个通道、10 个 CAN ID、正负过流阈值，保存、重启并读回；页面名称、命令边界和 `pcan_ivt_tool.py` 对齐。
- 增加 IVT 协议、出厂默认/目标/差异分类、ID 变更和 CAN1/模拟连接拒绝测试。

#### 审查项收敛和 Legacy 固件

- 修复 Q3 归因只按实际 Q3 保持/输出状态判断，避免 Debug-Bringup 关闭一级保护或告警刚出现的窗口把外部 HV_ACC 释放误记为 BMS 动作。
- 补充 CAN2 位率切换失败后的回滚结果和“位率未知”状态；失败恢复时清除旧 IVT 有效性，避免继续使用切换前数据。
- RTC 请求改为排队，连续请求不再互相覆盖；RTC 队列满返回状态 7，上位机按应答 Byte1 序列回显匹配。
- 故障帧与告警等级帧要求同时新鲜才组合显示；2 秒低频回报使用 2.5 秒窗口；断开/换设备清除 RTC 和充电计时旧状态；CANB 无单体原始数据时显示“无数据”而不是“模组离线”。
- `.bmslog` 加载阶段逐行校验所有帧；模拟器按 CAN1/CANB 边界、参数范围、保留字节和命令拒绝规则工作。
- 增加 `Release-Legacy` 固件身份解析。

- 本轮验证：50 项 Python 主机测试、PCAN 工具 Python 语法、JavaScript 语法和 `git diff --check` 通过；实体双 PCAN、真实 IVT、CANB 满载和 Windows 发布环境仍待验证。

#### 数据过期显示和台架边界

- 配置、单体累加、单体极值、继电器请求回读和运行诊断分别保留回报年龄；过期时参数控件清空或禁用，故障页和电芯页不再用旧阈值继续判断，过期的充电机类型不会覆盖“等待数据”。
- `pcan_bms_bench.py` 默认只在 CAN1 发送从控帧；真实 IVT 接 CANB。启用 `--canb-sop-ack`（兼容别名 `--sop-ack`）时，只接收真实 IVT 并发送 ECU SOP `0x4A4`，不发送 `0x512`。
- 增加单体累加/极值、阈值/开关/运行诊断独立过期测试、失联后趋势不再追加旧电气值，以及 CANB 上误发工具命令时优先提示总线限制的测试。

### 2026-08-03

#### 协议版本4同步

- 所有工具请求使用 `0x18A050F5`、固定 DLC=8；CANB BMS 状态/故障/告警使用 `0x4B0/0x4B1/0x4B2`，`0x401/0x402` 只按 Chroma 厂商报文解析；`0x186050F4` 按有符号电流和有效位解析；模拟器同步。无效或不完整的单体/温度极值不再显示为占位值或旧值。

#### 总状态有效性同步

- 总览只把 CAN1 `0x186050F4` 或 CANB `0x4B0` 作为包电压、电流、SOC 和单体/温度完整性的有效来源；`0x187650F4`/`0x4B1` 故障帧不再延长总状态的新鲜时间。
- 总状态帧超时或对应有效位为 0 时，包电压、电流、SOC、单体极值和温度极值显示“等待数据”，不继续显示上一条旧值；补充协议解码测试覆盖故障帧与总状态帧的独立超时。
- 写命令后端也要求最近 1.5 s 内收到总状态帧，不能仅凭故障帧中的旧状态继续发送配置或复位请求。

#### 提交前复核修正

- 修正构建日期解析的非闰年 2 月 29 日边界；运行诊断帧过期时不再回显旧充电机反馈；故障页把 bit22 显示为“事件触发”；补充日期边界测试。

#### 参数页和 Windows 发布入口收紧

- 参数页压缩标题、输入框、开关行和维护命令行的高度；“系统参数与维护命令”和“需要谨慎的操作”拆成左右两个同级面板，Flash 保存状态移到顶部命令条件栏。
- 充电请求回读拆成“请求值”和“充电机反馈”两个字段，分别表示主控保存的请求值与 Legacy/Chroma 充电机返回的实际值。
- 源码运行仍保留内置模拟数据供开发；PyInstaller 发布版固定使用真实 PCAN，隐藏工作模式选择并排除模拟器模块。发布版使用说明补充 Python、PCAN-Basic/驱动和 WebView2 的安装边界。

#### 状态机、IMD 和保存状态再次精简

- 状态机改为“状态机”标题在上、DOC/代码短状态名在下的纵向布局，使用 `SELF_TEST`、`STANDBY`、`PRECHARGE`、`HV_ON`、`FAULT` 并按状态着色。
