# BMS Control Desk 进度、待办与变更

本文档记录 CAN 上位机的剩余工作、风险、验证结果和已完成变更。原 `CHANGELOG.md` 的内容已经并入文末“已完成变更”节，本目录只保留这一份进度文件，不再单独维护 changelog。上位机进度、风险和验证以本文件为准，不在根目录 `todo.md` 重复登记；只有影响 F405 固件协议、安全行为或跨层联调的结论，才由根目录 `todo.md` 记录固件侧摘要。使用者说明见 [`../../DOC/CAN上位机与工具使用.md`](../../DOC/CAN上位机与工具使用.md)，安装和发布见 [`README.md`](README.md)。

## 当前状态

- CAN1、CANB 500 kbit/s、Legacy CANB 250 kbit/s和内置模拟数据已经接入。
- 已实现138串电压、48路温度、主控总览、故障与记录、独立参数与命令页、CAN记录/回放；高压、温度/冷却和 IMD 已按现场判断顺序分成直接可读的卡片。使用字段和页面顺序见 [`../../DOC/CAN上位机与工具使用.md`](../../DOC/CAN上位机与工具使用.md)。
- 在线写命令逐次确认，并核对总线、主控状态、请求计数、命令码和统一应答。
- 台架模拟从控和 IVT 配置已经拥有独立页面、独立连接和独立服务；默认收在“工程工具”折叠项中，不再通过底部连接方式切换。台架固定向 F405 CAN1 发送从控帧；真实 IVT-S 接 F405 CANB，台架不发送 `0x512`。
- 整车风扇工具页已接入：在 CANB 上解析 FanController `0x5A2/0x5A3/0x5A6/0x5A7` 状态并显示三路转速、两路占空比、温度和故障位；发送 `0x5A4` 命令（模式/温控曲线/失联策略/查询/恢复默认）并等待 `0x5A5` 按操作码和序号应答。命令编码与 FanController 仓库 `Doc/风扇控制.md` 的示例帧逐字节一致。
- 已同步 F405 协议版本4：所有工具请求使用 `0x18A050F5`、固定 DLC=8；CANB BMS 状态/故障/告警使用 `0x4B0/0x4B1/0x4B2`，`0x401/0x402` 只按 Chroma 厂商报文解析；`0x186050F4` 按有符号电流和有效位解析。无效或不完整的单体/温度极值不再显示为占位值或旧值；总览不再把故障帧当作总状态帧，状态帧过期或有效位为 0 时显示“等待数据”；后台写命令也拒绝没有新鲜总状态帧的发送。
- 工具页保留脚本的常用场景和命令输入；IVT 先读回并自动尝试出厂/目标 ID，再显示“已配置且一致”“未配置”或“配置不符”，一次性配置和 250/500 kbit/s 过渡操作分开显示。
- 主监视连接仍位于底部状态栏，只负责 BMS 上位机；工具页有自己的 PCAN 通道和连接按钮，支持主监视、台架和 IVT 分别维护状态。

## 已完成变更

### 2026-08-20

#### 悬浮提示稳定性修复

- 修复鼠标悬浮在单体电压/温度格上看“状态 · 最近数据 X s”时提示时有时无的问题。根因：每 250/500 ms 轮询后前端用 `innerHTML` 整块重建单体网格，鼠标下的元素被销毁重建，原生 title 提示的悬停计时被反复清零，弹出与否取决于悬停时机和轮询周期的竞态。
- 单体页改为首次进入时建好 6 模组 × 23 电压 + 8 温度的固定网格，之后每轮只原地更新数值、状态样式和 title；CANB 无单体原始数据的占位符也只在状态切换时写入一次。悬浮提示随轮询刷新数据年龄（保留 2 位小数），不再消失。
- 保护开关状态表（参数与命令页）同样改为启动时建一次、之后只改状态文字和样式，悬浮的名称/代码/变量提示保持稳定。
- CAN 监视器行按整行内容做签名复用：连续两轮内容完全一致时不做任何 DOM 操作，静止或暂停回放时悬浮查看完整数据/帧名稳定；有新帧时旧行节点保留并复用，只把新行插到顶部。筛选条件（方向/搜索）变化时重建行集，属于预期行为。
- 验证：59 项主机测试和 `node --check` 通过。DOM 复用逻辑经代码审查确认：固定 6×23/6×8 网格与快照固定 138/48 项数据一致（`protocol.py` 快照恒定输出该长度）、`onlyAbnormal` 语义与旧版一致（缺失值 `cellStatus` 返回 `invalid` 计入异常）、CANB 切换后网格重置重建、帧行池静止/暂停时零 DOM 操作。无自动化 UI 测试，实机悬浮效果待台架复核。

#### 接收时间戳与 RTC 校时显示修正

- 修复故障码变化记录、CAN 监视器时间列和 CSV/`.bmslog` 回放显示 1970 的问题。根因：python-can 的 PCAN 帧时间戳在环境缺少可选 `uptime` 库时是“适配器/系统启动以来的计数”，不是 Unix 时间；接收线程改为用收到帧时的上位机本机时间打戳（`CanService._frame_from_message`），历史记录、录制文件和回放显示统一走同一本机时钟。修改前录制的旧 CSV/`.bmslog` 文件内时间已经是错的，回放旧文件时无法恢复，以重新录制为准。
- RTC 校时按钮旁的状态不再在 5 秒后回到“等待新回复”：本次连接内持续显示最近一次校时应答和主控读回的时间；尚未校时时按主控周期上报的 RTC 有效性位（`0x186B50F4` bit7）显示“主控 RTC 有效”或“RTC 未校时”，收不到运行诊断帧时显示“等待数据”。
- 新增接收帧本机时间打戳用例和 RTC 应答持久性用例；`Tests/test_bms_host_protocol.py` 50 项全部通过，`node --check` 通过。

#### 从控未就绪和离线显示拆分

- 故障 bit16 显示“从控数据未就绪”；故障帧 Byte6 bit0..5 只显示超时窗口内完全收不到报文的从控离线状态，与固件新的在线/就绪判断一致。
- 故障帧格式版本字节随固件升为 0x03；模拟器和测试数据中的故障帧版本字节同步，上位机本身不校验该字节。
